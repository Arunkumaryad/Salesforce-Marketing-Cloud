# 1. Overview

In Salesforce Marketing Cloud Email Studio, several configuration
components work together when an email is sent.

The three important components covered in this documentation are:

``` text
Send Classification
        +
Sender Profile
        +
Delivery Profile
        ↓
Email Send
```

### Simple meaning

  -----------------------------------------------------------------------
  Component                           Main Purpose
  ----------------------------------- -----------------------------------
  **Send Classification**             Defines the nature of the send and
                                      combines sender + delivery settings

  **Sender Profile**                  Defines who the email appears to
                                      come from

  **Delivery Profile**                Defines delivery-related settings
                                      such as IP address, header and
                                      footer

  **CAN-SPAM Classification**         Determines whether the send is
                                      treated as Commercial or
                                      Transactional for the configured
                                      send classification
  -----------------------------------------------------------------------

# 3. Send Classifications

## What is a Send Classification?

A **Send Classification** is a Marketing Cloud configuration that brings
together the information required to classify and send an email.

It includes:

-   Name
-   External Key
-   Description
-   CAN-SPAM Classification
-   Sender Profile
-   Delivery Profile
-   Send Priority

The screenshots show the navigation:

``` text
Setup
  ↓
Feature Settings
  ↓
Email Studio
  ↓
Send Classifications
```

The **Send Classifications** page contains a **Create** button for
creating a new send classification.

------------------------------------------------------------------------

## Why do we use Send Classification?

A Send Classification helps Marketing Cloud determine:

1.  Whether the email is **Commercial** or **Transactional**.
2.  Which **Sender Profile** should be used.
3.  Which **Delivery Profile** should be used.
4.  The send priority.

### Simple Example

Suppose we want to send an invoice email.

``` text
Send Classification
Name:
InvoiceTransaction_Arun

CAN-SPAM Classification:
Transactional

Sender Profile:
InvoiceTransaction_Arun

Delivery Profile:
InvoiceTransaction_DP_Arun
```

This configuration can then be selected when setting up the appropriate
email send.

# 4. Commercial vs Transactional

The training material presents two send classifications.

## 4.1 Commercial

### Examples shown in the training material

-   Promotional emails
-   Newsletter emails

### Easy Explanation

A commercial email primarily promotes or advertises a product, service,
offer, campaign, or other commercial content.

Examples:

``` text
20% OFF SALE
```

``` text
New Product Launch
```

``` text
Weekend Special Offer
```

``` text
Monthly Newsletter
```

These are normally treated as **Commercial** communications.

------------------------------------------------------------------------

## 4.2 Transactional

### Examples shown in the training material

#### Forgot Password

A `"forgot my password"` email for a customer account.

The customer needs and triggers this email regardless of their
newsletter subscription.

``` text
Customer
   ↓
Requests Password Reset
   ↓
Password Reset Email
```

#### Double Opt-In Confirmation Request

The training material gives this example:

> `"Double Opt In Confirmation Request" emails - if the user demonstrably WANTS to re-subscribe, this message HAS to be sent or that transaction cannot be completed.`

### Easy Explanation

A transactional email is generally connected to an action or transaction
that the customer has requested or initiated.

Examples:

-   Password reset
-   Order confirmation
-   Shipping notification
-   Reservation confirmation
-   Account-related notifications
-   Double opt-in confirmation

# 5. CAN-SPAM

## 5.1 Definition shown in the screenshot

The screenshot states:

> **The CAN-SPAM Act imposes stricter requirements on Commercial email
> than on Transactional email. Complying with these requirements
> protects you from CAN-SPAM litigation and demonstrates your commitment
> to providing relevant customer messaging.**

The screenshot further states:

> **The CAN-SPAM act requires that Commercial emails, whose primary
> purpose is to deliver commercial content, meet the following
> criteria:**

### Requirement 1 --- Accurately identify the sender

> **Accurately identify the sender in the header information.**

### Requirement 2 --- Accurate subject line

> **Use a subject line that accurately represents the content of the
> email.**

### Requirement 3 --- Identify the advertisement

> **Identify the message as an advertisement, unless you have express
> consent (opt-in) from the subscriber.**

### Requirement 4 --- Physical mailing address

> **Include your physical mailing address.**

### Requirement 5 --- Opt-out mechanism

> **Provide a mechanism to opt out. You cannot require a subscriber to
> log in or visit more than a single page to unsubscribe.**

### Requirement 6 --- Honor opt-out requests

> **Honor opt-out requests promptly. You must process an unsubscribe
> request within 10 days, and your unsubscribe mechanism must be
> operational for at least 30 days after the mailing.**

------------------------------------------------------------------------

## 5.2 Easy Explanation of CAN-SPAM

For commercial email, remember:

``` text
Accurate Sender
      +
Accurate Subject
      +
Advertisement Identification
      +
Physical Mailing Address
      +
Easy Unsubscribe
      +
Prompt Opt-Out Processing
```

------------------------------------------------------------------------

## 5.3 Important CAN-SPAM concept in Marketing Cloud

The Send Classification screen contains a **CAN-SPAM Classification**
field with options such as:

``` text

```

The screen explains that **Commercial** and **Transactional** have legal
meanings under the U.S. Federal CAN-SPAM Act.

### Definition shown in the screenshot

The email is automatically sent because a specific event/action occurs.

``` text
Customer Purchase
       ↓

       ↓
Marketing Cloud
       ↓
Confirmation Email
```

Examples:

-   Password reset
-   Order confirmation
-   Registration confirmation

# 13.2 User-Initiated Send

### Definition shown in the screenshot

      ↓

## Triggered vs User-Initiated

The screenshot summarizes the difference:

> **A user-defined email message interaction occurs when you manually

  --------------------------------- --------------------------------

  Usually individual/event-driven   Usually audience/list/DE based

# 14. Personalized and Dynamic Email

The training material includes an example of a **Personalized & Dynamic
Email**.

## What is personalization?

Personalization means displaying subscriber-specific information.

Example:

``` text
Hi, Hanna!
```

instead of:

``` text
Hi, Customer!
```

Common personalization fields:

-   First Name
-   Last Name
-   Customer Name
-   Product
-   Account Information
-   Location
-   Preference

------------------------------------------------------------------------

## What is Dynamic Content?

Dynamic content means different content can be displayed to different
subscribers based on data or rules.

Example:

``` text
Customer Type
     |
     +-- VIP       → VIP Offer
     |
     +-- Regular   → Standard Offer
     |
     +-- New       → Welcome Offer
```

------------------------------------------------------------------------

## Personalization vs Dynamic Content

  Personalization           Dynamic Content
  ------------------------- ---------------------------------------
  Changes specific values   Changes content blocks/sections
  Example: `Hi John`        Example: VIP banner vs regular banner
  Usually field based       Usually rule/segment based

> Subscribers who experience these bounces are marked as "Bounced".**

The training material also states:

> **Once an email campaign has been sent, Marketing Cloud users no
> longer have any control over the bounces. You can only understand the
> reasons for a bounce and what the consequences are for future
> mailings.**

------------------------------------------------------------------------

## Two Types of Bounces

``` text
Bounce
  |
  +-- Soft Bounce
  |
  +-- Hard Bounce
```

------------------------------------------------------------------------

# 16. Soft Bounce

## Definition shown in the screenshot

> **A soft bounce is an email that is rejected by an email server for a
> temporary reason. An example of this would be a full inbox.**

------------------------------------------------------------------------

## Soft Bounce Examples

-   Full mailbox
-   Temporary server issue
-   Temporary receiving-server unavailability
-   Temporary delivery problem

### Example

``` text
Marketing Cloud
      ↓
Email Sent
      ↓
Recipient Server
      ↓
Mailbox Full
      ↓
Soft Bounce
```

------------------------------------------------------------------------

## Soft Bounce Considerations from the training material

The training material states:

> **In the case of a soft bounce, Marketing Cloud tries to resend the
> email to the subscriber every 15 minutes for 72 hours, i.e., 288
> times. After this period, the subscriber's status is marked as
> Bounced. Once a bounce appears in the tracking, it cannot be
> changed.**

It also states:

> **The 288 attempts are not counted individually as a bounce, but all
> together as 1 unsuccessful attempt. If all 288 attempts fail, the
> Subscriber Status is set to Bounced. If the subscriber opens one of
> the 288 attempts, the status is changed to Active. This also applies
> to opening an old email in the Inbox.**

Finally, the training material states:

> **3 soft bounces in a span of 15 days will result into Hard Bounce.**

### Important

These retry numbers and bounce rules are reproduced from the supplied
training material. Marketing Cloud behavior can change by product
version/configuration, so production implementations should be validated
against current Salesforce documentation.

# 18. Subscriber Status

## Definition shown in the training material

The available statuses in Marketing Cloud are:

### Active

> **Active --- green: able to receive emails with no issues**

### Bounced

> **Bounced --- yellow: one or more bounces (soft or hard) are received
> for the subscriber**

### Unsubscribed

> **Unsubscribed --- red: unable to receive emails due to an
> unsubscribe**

### Undeliverable / Held

> **Undeliverable/held --- grey: deactivated due to repeated bounces. If
> the bounce was from a trusted domain, only one hard bounce is
> required.**

------------------------------------------------------------------------

## Status Summary

  -----------------------------------------------------------------------
  Status                              Meaning
  ----------------------------------- -----------------------------------
  **Active**                          Able to receive emails with no
                                      issues

  **Bounced**                         One or more soft/hard bounces
                                      received

  **Unsubscribed**                    Subscriber has unsubscribed

  **Held / Undeliverable**            Deactivated/suppressed due to
                                      qualifying delivery failures
  -----------------------------------------------------------------------

# 20. Subscriber Key

## Definition shown in the training material

> **In Email Studio, contacts are identified by the Subscriber Key,
> which becomes the Contact Key in Contact Builder.**

> **The Subscriber Key is the primary key for your subscribers and
> allows you to identify subscribers with a value that you choose.**

------------------------------------------------------------------------

## Easy Explanation

Subscriber Key is the unique identifier used to identify a subscriber.

Example:

``` text
Subscriber Key:
CUST1001

Email:
john@example.com
```

The Subscriber Key can be based on a stable business identifier such as:

-   Customer ID
-   CRM ID
-   Contact ID
-   Loyalty ID
-   External system ID

------------------------------------------------------------------------

## Subscriber Key vs Email Address

  Subscriber Key                 Email Address
  ------------------------------ ----------------------------------
  Identifies the subscriber      Identifies the email destination
  Should generally be stable     Can change
  Can be Customer ID / CRM ID    Usually email format
  Used for subscriber identity   Used for delivery

### Example

Before:

``` text
Subscriber Key = CUST1001
Email = john@gmail.com
```

After email change:

``` text
Subscriber Key = CUST1001
Email = john.smith@gmail.com
```

The subscriber identity remains the same because the Subscriber Key
remains unchanged.

# 23. Interview Questions and Answers

## Q1. What is a Send Classification?

**Answer:**

A Send Classification is a Marketing Cloud configuration used to define
the type/nature of an email send and associate a Sender Profile and
Delivery Profile with that send. It also includes send priority and
CAN-SPAM classification.

------------------------------------------------------------------------

## Q2. What are the main components of a Send Classification?

**Answer:**

The main components shown in the configuration are:

-   Name
-   External Key
-   Description
-   CAN-SPAM Classification
-   Sender Profile
-   Delivery Profile
-   Send Priority

------------------------------------------------------------------------

## Q3. What is the difference between Commercial and Transactional email?

**Answer:**

A Commercial email primarily contains promotional or advertising
content, such as promotions and newsletters. A Transactional email
primarily facilitates, completes, or confirms a transaction or
customer-requested action, such as a password reset or purchase
confirmation.

------------------------------------------------------------------------

## Q4. Give examples of Commercial emails.

**Answer:**

-   Promotional emails
-   Newsletter emails
-   Discount campaigns
-   Product promotions
-   Sales campaigns

------------------------------------------------------------------------

## Q5. Give examples of Transactional emails.

**Answer:**

-   Password reset
-   Purchase confirmation
-   Shipping notification
-   Reservation confirmation
-   Double opt-in confirmation

------------------------------------------------------------------------

## Q6. What is a Sender Profile?

**Answer:**

A Sender Profile specifies the From information that displays in the
recipient's inbox. It primarily controls the From Name and From Email.

------------------------------------------------------------------------

## Q7. What is a Delivery Profile?

**Answer:**

A Delivery Profile controls delivery-related settings such as the IP
address, header, and footer used for the email.

------------------------------------------------------------------------

## Q8. What is the difference between Sender Profile and Delivery Profile?

**Answer:**

A Sender Profile controls **who the email appears to come from**, while
a Delivery Profile controls **how the email is delivered**, including
settings such as IP, header, and footer.

------------------------------------------------------------------------

## Q9. What is the difference between Send Classification and Sender Profile?

**Answer:**

A Sender Profile only defines sender information such as From Name and
From Email.

A Send Classification is a broader configuration that can specify the
CAN-SPAM classification and associate the Sender Profile and Delivery
Profile with the send.

------------------------------------------------------------------------

## Q10. What is the difference between Send Classification and Delivery Profile?

**Answer:**

A Send Classification defines the overall send classification and
references a Delivery Profile. The Delivery Profile itself contains
delivery settings such as IP address, header, and footer.

------------------------------------------------------------------------

## Q11. Why do we verify the From Email address?

**Answer:**

The sending address should be verified and authorized before it is used
as a sending identity. This helps ensure that the organization is
permitted to send from the address/domain and supports proper email
deliverability configuration.

------------------------------------------------------------------------

## Q12. What is CAN-SPAM?

**Answer:**

CAN-SPAM is a U.S. law that establishes requirements for commercial
email and provides recipients with the right to opt out of future
commercial email.

------------------------------------------------------------------------

## Q13. What are the important CAN-SPAM requirements?

**Answer:**

For commercial email, important requirements include:

1.  Accurately identify the sender.
2.  Use an accurate subject line.
3.  Properly identify the message as an advertisement where required.
4.  Include a physical mailing address.
5.  Provide an easy opt-out mechanism.
6.  Honor opt-out requests promptly.

------------------------------------------------------------------------

## Q14. Why is an unsubscribe link important for Commercial emails?

**Answer:**

Commercial emails generally need a clear opt-out mechanism so recipients
can stop receiving future commercial messages.

------------------------------------------------------------------------

## Q15. What happens if the user selects Transactional classification?

**Answer:**

Marketing Cloud treats the configured send as transactional according to
the selected classification. The Send Classification screen notes that
transactional messages are subject to different CAN-SPAM handling and
that Marketing Cloud does not check for an unsubscribe link for
transactional classification.

The classification must be appropriate for the actual primary purpose of
the email.

------------------------------------------------------------------------

## Q16. What is a Triggered Send?

**Answer:**

A Triggered Send is an email sent to an individual subscriber in
response to an action or event, such as a purchase.

------------------------------------------------------------------------

## Q17. What is a User-Initiated Send?

**Answer:**

A User-Initiated Send is an email interaction that a Marketing Cloud
user manually starts for a subscriber list or Data Extension.

------------------------------------------------------------------------

## Q18. What is the difference between Triggered Send and User-Initiated Send?

**Answer:**

A Triggered Send occurs in response to an action, event, or API call. A
User-Initiated Send is manually started by a Marketing Cloud user.

------------------------------------------------------------------------

## Q19. What is a Soft Bounce?

**Answer:**

A Soft Bounce is generally a temporary delivery failure, such as a
recipient mailbox being full.

------------------------------------------------------------------------

## Q20. What is a Hard Bounce?

**Answer:**

A Hard Bounce is generally a permanent delivery failure, such as an
unknown domain or invalid recipient.

------------------------------------------------------------------------

## Q21. What is Bounce Mail Management?

**Answer:**

Bounce Mail Management deals with delivery failure messages returned by
the receiving mail system/ISP and the resulting subscriber delivery
status.

------------------------------------------------------------------------

## Q22. What are the subscriber statuses mentioned in the training?

**Answer:**

-   Active
-   Bounced
-   Unsubscribed
-   Undeliverable/Held

------------------------------------------------------------------------

## Q23. What does Active mean?

**Answer:**

Active means the subscriber is able to receive emails with no issues,
subject to the specific send and subscription context.

------------------------------------------------------------------------

## Q24. What does Bounced mean?

**Answer:**

Bounced means one or more soft or hard bounces have been received for
the subscriber.

------------------------------------------------------------------------

## Q25. What does Unsubscribed mean?

**Answer:**

Unsubscribed means the subscriber has opted out and is unable to receive
applicable marketing emails.

------------------------------------------------------------------------

## Q26. What does Held mean?

**Answer:**

Held/Undeliverable means the subscriber has been deactivated or
suppressed due to qualifying repeated delivery failures.

------------------------------------------------------------------------

## Q27. What is a Subscriber Key?

**Answer:**

Subscriber Key is the unique identifier used to identify a subscriber in
Email Studio. The training material states that it becomes the Contact
Key in Contact Builder.

------------------------------------------------------------------------

## Q28. Why should Subscriber Key be stable?

**Answer:**

A stable Subscriber Key allows Marketing Cloud to continue identifying
the same subscriber even if the subscriber's email address changes.

------------------------------------------------------------------------

## Q29. What is All Subscribers?

**Answer:**

All Subscribers is considered the master list of records for the
Marketing Cloud Email Studio account and contains subscriber records and
their email status.

------------------------------------------------------------------------

## Q30. What is a List in Marketing Cloud?

**Answer:**

A List is a collection of subscribers used to manage a relatively simple
subscriber model in Email Studio.

------------------------------------------------------------------------

## Q31. What is Personalization?

**Answer:**

Personalization means using subscriber-specific data in an email, such
as displaying the recipient's first name.

Example:

``` text
Hi John,
```

instead of:

``` text
Hi Customer,
```

------------------------------------------------------------------------

## Q32. What is Dynamic Content?

**Answer:**

Dynamic Content displays different content to different subscribers
based on rules, attributes, or segmentation.

------------------------------------------------------------------------

## Q33. What is the difference between personalization and dynamic content?

**Answer:**

Personalization changes specific subscriber values, such as a name.
Dynamic Content can change larger content blocks or sections based on
subscriber data and rules.

------------------------------------------------------------------------

# 25. Important Notes

## 25.1 Exact training definitions vs practical explanation

The quoted definitions in this README are intentionally kept close to
the wording visible in the supplied screenshots because the purpose of
this repository is to document the training material.

The sections labeled **Easy Explanation** are simplified explanations
added for learning and interview preparation.

------------------------------------------------------------------------

## 25.2 CAN-SPAM legal wording

The screenshots contain training/course wording about CAN-SPAM. Legal
requirements can be updated or depend on the exact nature of an email
and organization.

For production/compliance decisions, confirm the current legal
requirements and consult the organization's legal/compliance team.

------------------------------------------------------------------------

## 25.3 Transactional classification should be used carefully

Do not classify an email as Transactional merely because it contains
some transactional information.

The actual purpose and content of the email matter.

A message that is primarily promotional should not be incorrectly
classified as transactional just to avoid unsubscribe handling.

------------------------------------------------------------------------

## 25.4 Email authentication

Using an authenticated sending domain is important for deliverability
and sender reputation.

The Sender Profile screen shown in the training material warns about
using an unauthenticated From domain.
