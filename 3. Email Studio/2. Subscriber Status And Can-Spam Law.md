# 1. Email Studio Overview

**Email Studio** is a Salesforce Marketing Cloud Engagement application
used to create, manage, send, and track email communications.

### Email Studio can be used to create:

-   **Promotional emails**
    -   Newsletters
    -   Promotions
    -   Flash sales
    -   Loyalty programs
    -   Events
    -   Coupons
-   **Transactional and triggered emails**
    -   Hotel reservation confirmations
    -   Purchase confirmations
    -   Shipping notifications
    -   Overdraft alerts
    -   Bank statements
-   **E-commerce emails**
    -   Abandoned shopping cart emails
    -   Order confirmations
    -   Next-best-offer recommendations
    -   Receipts

### Simple Example

Suppose an online shopping company wants to:

1.  Send a discount coupon → **Promotional email**
2.  Send an order confirmation → **Transactional email**
3.  Remind a customer about an abandoned cart → **E-commerce / triggered
    email**

# 2. Email Studio Lists

## Definition from the training material

> **Lists are a default method of storing data in Marketing Cloud Email
> Studio.**

> **You can set different attributes to your subscribers using lists,
> which represent a collection of subscribers.**

> **You can only use lists if your Subscriber count is below 500,000.**

> **Lists work best to manage a relatively simple subscriber model that
> doesn't contain other commercial or transactional information.**

### What is a List?

A **List** is a collection of subscribers in Email Studio. It is a
relatively simple way of organizing subscribers and storing subscriber
attributes.

For example:

``` text
Newsletter Subscribers
        |
        |-- John
        |-- Sarah
        |-- David
        |-- Priya
```

Each subscriber can have attributes such as:

-   Subscriber Key
-   Email Address
-   First Name
-   Last Name
-   Subscriber Status
-   Other profile attributes

### When should Lists be used?

Lists are suitable when:

-   The subscriber model is simple.
-   You do not need a complex relational data model.
-   You have a relatively small subscriber base.
-   You mainly need basic subscriber/profile attributes.

### Lists vs Data Extensions

  -----------------------------------------------------------------------
  Feature                 List                    Data Extension
  ----------------------- ----------------------- -----------------------
  Data model              Simple                  Flexible/relational

  Best for                Basic subscriber        Complex marketing data
                          management              

  Fields                  Subscriber attributes   Custom fields

  Relationships           Limited                 Can be modeled using
                                                  keys

  Large/complex data      Not ideal               Preferred

  Segmentation            Basic                   Much more flexible

  Typical use             Simple subscriber lists Campaign, customer,
                                                  transactional and
                                                  behavioral data
  -----------------------------------------------------------------------

**Interview tip:** In modern Marketing Cloud implementations, **Data
Extensions are generally preferred for complex and scalable data
models**.

# 3. Subscriber Key

## Definition from the training material

> **In Email Studio, contacts are identified by the Subscriber Key,
> which becomes the Contact Key in Contact Builder.**

> **The Subscriber Key is the primary key for your subscribers and
> allows you to identify subscribers with a value that you choose.**

### What is Subscriber Key?

A **Subscriber Key** is a unique identifier used to identify a
subscriber in Marketing Cloud Engagement.

Salesforce describes it as a text field containing a value that uniquely
identifies a subscriber in Marketing Cloud Engagement.

A Subscriber Key can be:

-   Customer ID
-   Contact ID
-   Lead ID
-   CRM ID
-   Loyalty ID
-   External System ID

### Example

Suppose:

``` text
Customer ID = CUST1001
Email       = john@gmail.com
```

You can use:

``` text
Subscriber Key = CUST1001
Email Address  = john@gmail.com
```

### Why not always use Email Address as Subscriber Key?

Email addresses can change.

Example:

``` text
Subscriber Key = CUST1001
Old Email      = john@gmail.com

Later:

Subscriber Key = CUST1001
New Email      = john.smith@gmail.com
```

The customer remains the same because the **Subscriber Key stays the
same**.

### Subscriber Key vs Email Address

  -----------------------------------------------------------------------
  Subscriber Key                      Email Address
  ----------------------------------- -----------------------------------
  Identifies the subscriber           Delivery address

  Should be stable                    Can change

  Can be CRM/Customer ID              Usually an email

  Used for subscriber identity        Used for email delivery

  Recommended as a business           Should not normally be the primary
  identifier                          identity
  -----------------------------------------------------------------------

### Important

A Subscriber Key can allow the same email address to appear against
different subscriber keys.

Example:

``` text
Subscriber Key | Email
---------------|------------------
CUSTOMER001    | family@example.com
CUSTOMER002    | family@example.com
```

These can represent two different subscribers even though the email
address is the same.

# 4. All Subscribers List

## Definition from the training material

> **The All-Subscribers list is considered the master list of records
> for the Marketing Cloud Email Studio account.**

> **Every subscriber in your account appears in the All-Subscribers
> list. Subscribers added to a subscriber list join the All-Subscribers
> list at the same time.**

> **Subscribers stored on data extensions join the All-Subscribers list
> when you send your first message to that subscriber.**

### What is All Subscribers?

**All Subscribers** is the central subscriber-status repository in Email
Studio.

It contains the subscriber's:

-   Subscriber Key
-   Email Address
-   Subscriber Status
-   Subscription/unsubscription information

### Important relationship

``` text
                    ALL SUBSCRIBERS
                         |
        -------------------------------------
        |                 |                 |
      Lists          Data Extensions    Other Send Sources
```

When a subscriber becomes known to Email Studio, the All Subscribers
record is used to maintain subscriber-level email status.

### Important unsubscribe behavior

If a subscriber is unsubscribed at the **All Subscribers** level, the
subscriber is unsubscribed from all lists and groups.

However, list/group subscription states can be different from the All
Subscribers state. Reactivating the subscriber at All Subscribers does
not automatically mean that the subscriber has opted back into every
individual list/group.

### Example

``` text
All Subscribers
Customer001 → Unsubscribed

Newsletter List
Customer001 → Unsubscribed

Promotions List
Customer001 → Unsubscribed
```

If the subscriber is globally unsubscribed, Marketing Cloud should not
send marketing email to that subscriber.

# 5. Subscriber Status

The training material describes these subscriber statuses:

  -----------------------------------------------------------------------
  Status                              Meaning
  ----------------------------------- -----------------------------------
  **Active**                          Subscriber can receive emails

  **Bounced**                         One or more bounces have been
                                      received

  **Unsubscribed**                    Subscriber has unsubscribed and
                                      cannot receive applicable email
                                      sends

  **Undeliverable / Held**            Subscriber has been deactivated
                                      because of repeated/qualifying
                                      delivery failures
  -----------------------------------------------------------------------

Salesforce currently documents the major subscriber statuses as
**Active, Unsubscribed, Held, and Bounced**.

------------------------------------------------------------------------

## 5.1 Active

### Definition from the training material

> **Active --- green: able to receive emails with no issues**

### Simple explanation

An **Active** subscriber is eligible to receive an email, assuming the
send and subscription context also allow the message.

Example:

``` text
Subscriber Key: CUST1001
Email: john@example.com
Status: Active
```

------------------------------------------------------------------------

## 5.2 Bounced

### Definition from the training material

> **Bounced --- yellow: one or more bounces (soft or hard) are received
> for the subscriber**

### Simple explanation

A **Bounce** means the receiving mail server did not accept delivery of
an email.

Bounces can be:

-   Soft bounce
-   Hard bounce

------------------------------------------------------------------------

## 5.3 Unsubscribed

### Definition from the training material

> **Unsubscribed --- red: unable to receive emails due to an
> unsubscribe**

### Simple explanation

An **Unsubscribed** subscriber has opted out of receiving applicable
marketing email.

Example:

``` text
Customer clicks:
"Unsubscribe"

↓

Subscriber Status:
Unsubscribed
```

Marketing Cloud uses this status to prevent future applicable marketing
sends.

------------------------------------------------------------------------

## 5.4 Undeliverable / Held

### Definition from the training material

> **Undeliverable/Held --- grey: deactivated due to repeated bounces. If
> the bounce was from a trusted domain, only one hard bounce is
> required.**

### Simple explanation

**Held** means the subscriber has been suppressed/deactivated because
Marketing Cloud considers the address undeliverable based on bounce
behavior.

Salesforce documentation uses **Held** for this state and provides
procedures for reactivating held subscribers.

# 6. Bounce Mail Management

## Definition from the training material

> **Bounces are messages sent back to Marketing Cloud by an Internet
> Service Provider (ISP) explaining why an email could not be delivered.
> Subscribers who experience these bounces are marked as "Bounced".**

### What is a Bounce?

A bounce occurs when an email cannot be successfully delivered to the
recipient's mail server/mailbox.

Example:

``` text
Marketing Cloud
      |
      | Email
      v
Recipient Mail Server
      |
      X
Delivery failed
      |
      v
Bounce response
      |
      v
Marketing Cloud
```

Marketing Cloud uses bounce information to manage subscriber delivery
status.

------------------------------------------------------------------------

# 7. Soft Bounce

## Definition from the training material

> **A soft bounce is an email that is rejected by an email server for a
> temporary reason. An example of this would be a full inbox.**

### Common soft-bounce situations

Examples include:

-   Recipient mailbox is full
-   Temporary mail-server problem
-   Temporary throttling
-   Temporary recipient-server issue

### Training material behavior

The screenshot states:

> **In the case of a soft bounce, Marketing Cloud tries to resend the
> email to the subscriber every 15 minutes for 72 hours, i.e., 288
> times. After this period, the subscriber's status is marked as
> Bounced.**

It also states:

> **The 288 attempts are not counted individually as a bounce, but all
> together as 1 unsuccessful attempt. If all of 288 attempts fail, the
> Subscriber Status is set to Bounced. If the subscriber opens one of
> the 288 attempts, the status is changed to Active. This also applies
> to opening an old email in the inbox.**

And:

> **3 soft bounces in a span of 15 days will result into Hard Bounce.**

### Important clarification

Treat the above retry numbers and the "3 soft bounces in 15 days"
statement as **training-material behavior**, not as a universal rule to
apply to every current Marketing Cloud configuration.

Bounce handling can depend on current Marketing Cloud/Engagement
behavior and mailbox/provider responses. For production decisions,
verify the current Salesforce documentation and your account
configuration.

------------------------------------------------------------------------

# 8. Hard Bounce

## Definition from the training material

> **A hard bounce is a rejection of an email for a permanent reason,
> such as an unknown domain.**

### Common hard-bounce examples

-   Invalid/unknown domain
-   Non-existent recipient
-   Permanently rejected address
-   Invalid mailbox

Example:

``` text
Email:
john@doesnotexist12345.com

Receiving server:
Domain does not exist

Result:
Hard Bounce
```

### Soft Bounce vs Hard Bounce

  -----------------------------------------------------------------------
  Soft Bounce                         Hard Bounce
  ----------------------------------- -----------------------------------
  Usually temporary                   Usually permanent

  Mailbox may be full                 Address/domain may not exist

  Temporary server issue              Permanent delivery failure

  Delivery may succeed later          Delivery generally will not succeed
                                      without correcting the address

  Example: full inbox                 Example: unknown domain
  -----------------------------------------------------------------------

# 9. CAN-SPAM Law

## What is CAN-SPAM?

**CAN-SPAM** stands for the **Controlling the Assault of Non-Solicited
Pornography And Marketing Act of 2003**.

It establishes requirements for commercial email and gives recipients
the right to opt out of future commercial email.

The law is enforced by the U.S. Federal Trade Commission (FTC).

------------------------------------------------------------------------

## CAN-SPAM requirements from the training material

The screenshots state that CAN-SPAM requires commercial emails to:

### 1. Accurately identify the sender

> **Accurately identify the sender in the header information.**

The From, To, Reply-To and routing information must not be false or
misleading.

### 2. Use an accurate subject line

> **Use a subject line that accurately represents the content of the
> email.**

Example:

Bad:

``` text
Subject: Your account has been suspended
```

when the email is actually just a promotion.

Better:

``` text
Subject: 20% Off Your Next Order
```

when the email really contains a 20% promotion.

### 3. Identify commercial messages appropriately

The training screenshot says:

> **Identify the message as an advertisement, unless you have express
> consent (opt-in) from the subscriber.**

**Current FTC wording is broader:** commercial email generally must be
identified as an advertisement unless an applicable exception applies.
Do not interpret the screenshot wording as meaning that express consent
is the only factor determining whether the ad-identification requirement
applies.

### 4. Include a physical mailing address

> **Include your physical mailing address.**

The message must contain a valid physical postal address.

This can generally be:

-   A current street address
-   A properly registered P.O. Box
-   A qualifying private mailbox

### 5. Provide an opt-out mechanism

> **Provide a mechanism to opt out. You cannot require a subscriber to
> log in or visit more than a single page to unsubscribe.**

The unsubscribe process should be:

-   Clear
-   Easy to understand
-   Easy to use
-   Free
-   Not dependent on unnecessary information

### 6. Honor opt-out requests promptly

The screenshot states:

> **Honor opt-out requests promptly. You must process an unsubscribe
> request within 10 days, and your unsubscribe mechanism must be
> operational for at least 30 days after the mailing.**

### Current FTC clarification

The FTC currently states that opt-out requests must be honored within
**10 business days**, and the opt-out mechanism must remain operational
for at least **30 days** after the commercial email is sent.

# 10. Commercial vs Transactional Email

Understanding this difference is important in interviews.

## Commercial Email

A commercial email primarily promotes or advertises:

-   Products
-   Services
-   Offers
-   Discounts
-   Sales
-   Promotions

Example:

``` text
Subject:
Get 30% Off This Weekend
```

This is a commercial/promotional message.

------------------------------------------------------------------------

## Transactional / Relationship Email

A transactional or relationship message is primarily about an existing
transaction or relationship with the recipient.

Examples:

-   Order confirmation
-   Shipping notification
-   Password reset
-   Account statement
-   Reservation confirmation

Example:

``` text
Subject:
Your Order #10025 Has Shipped
```

The primary purpose is to communicate transaction information.

### Important

Do not assume that adding a small transactional sentence makes a
commercial email transactional.

The **primary purpose of the message** matters.

# 12. Interview Questions and Answers

## Q1. What is a Subscriber Key?

**Answer:**

A Subscriber Key is a unique value used to identify a subscriber in
Marketing Cloud Engagement. It is the subscriber's primary identifier
and can be a CRM ID, Customer ID, Lead ID, Contact ID, or another stable
business identifier.

------------------------------------------------------------------------

## Q2. Why should we avoid using Email Address as Subscriber Key?

**Answer:**

Because an email address can change. A stable Customer ID or CRM ID
allows the same person to remain identifiable even after their email
address changes.

------------------------------------------------------------------------

## Q3. What is the difference between Subscriber Key and Email Address?

**Answer:**

Subscriber Key identifies **who the subscriber is**, while Email Address
identifies **where the email is delivered**.

------------------------------------------------------------------------

## Q4. What is All Subscribers?

**Answer:**

All Subscribers is the central/master subscriber list in Email Studio
that maintains subscriber records and subscriber-level email status.

------------------------------------------------------------------------

## Q5. What happens when a subscriber is unsubscribed from All Subscribers?

**Answer:**

The subscriber is unsubscribed from all lists and groups at the All
Subscribers level. They should not receive applicable marketing email
unless they subsequently provide valid permission and are reactivated
according to the appropriate subscription process.

------------------------------------------------------------------------

## Q6. Can a subscriber be Active in All Subscribers but Unsubscribed from a particular list?

**Answer:**

Yes. A subscriber can be active at the All Subscribers level but
unsubscribed from a specific list/group.

------------------------------------------------------------------------

## Q7. What is a Bounce?

**Answer:**

A bounce is a delivery failure response sent back by the receiving mail
system/ISP indicating that the email could not be delivered.

------------------------------------------------------------------------

## Q8. What is a Soft Bounce?

**Answer:**

A soft bounce is generally a temporary delivery failure, such as a full
mailbox or temporary receiving-server problem.

------------------------------------------------------------------------

## Q9. What is a Hard Bounce?

**Answer:**

A hard bounce is generally a permanent delivery failure, such as an
invalid recipient or unknown domain.

------------------------------------------------------------------------

## Q10. What is Held status?

**Answer:**

Held (also called Undeliverable in some Email Studio UI/search
terminology) indicates that Marketing Cloud has deactivated/suppressed
the subscriber because of qualifying delivery failures.

------------------------------------------------------------------------

## Q11. What are the major subscriber statuses?

**Answer:**

The major statuses are:

-   Active
-   Bounced
-   Unsubscribed
-   Held / Undeliverable

------------------------------------------------------------------------

## Q12. What is CAN-SPAM?

**Answer:**

CAN-SPAM is a U.S. law governing commercial email. It requires accurate
sender information, non-deceptive subject lines, appropriate advertising
identification, a valid physical postal address, and a clear opt-out
mechanism.

------------------------------------------------------------------------

## Q13. What are the important CAN-SPAM requirements?

**Answer:**

1.  Do not use false or misleading header information.
2.  Do not use deceptive subject lines.
3.  Properly identify commercial/advertising messages.
4.  Include a valid physical postal address.
5.  Provide a clear opt-out mechanism.
6.  Honor opt-out requests promptly.
7.  Keep the opt-out mechanism operational for at least 30 days after
    the message.

------------------------------------------------------------------------

## Q14. How quickly must an unsubscribe request be honored?

**Answer:**

The FTC states that a CAN-SPAM opt-out request must be honored within
**10 business days**.

------------------------------------------------------------------------

## Q15. How long should the unsubscribe mechanism remain operational?

**Answer:**

The FTC states that it must remain operational for at least **30 days
after the commercial email is sent**.

------------------------------------------------------------------------

## Q16. Does CAN-SPAM apply only to emails sent without consent?

**Answer:**

No. CAN-SPAM requirements apply to commercial email broadly; obtaining
consent does not eliminate the need to follow applicable requirements.

------------------------------------------------------------------------

## Q17. What is the difference between commercial and transactional email?

**Answer:**

Commercial email primarily promotes a product/service or commercial
offer. Transactional/relationship email primarily communicates
information about an existing transaction or relationship, such as an
order confirmation or shipping notification.

------------------------------------------------------------------------

## Q18. Why is Subscriber Key important for Contact Builder?

**Answer:**

The Subscriber Key is used as the subscriber identity in Email Studio
and corresponds to the Contact Key used to identify the contact in
Contact Builder.

------------------------------------------------------------------------

## Q19. Can two people have the same email address?

**Answer:**

Yes. Different Subscriber Keys can be associated with the same email
address.

Example:

``` text
CUST001 → family@example.com
CUST002 → family@example.com
```

Marketing Cloud can distinguish the subscribers using their Subscriber
Keys.

------------------------------------------------------------------------

## Q20. What happens when a Data Extension subscriber is sent an email for the first time?

**Answer:**

The subscriber can be added to the All Subscribers repository when the
first applicable message is sent, depending on the send configuration
and current Marketing Cloud behavior.

# 14. Important Notes About the Training Screenshots

Some statements in the supplied screenshots are training-oriented and
may reflect the behavior/documentation available when the material was
created.

### 1. List subscriber limit

The screenshot says:

> "You can only use lists if your Subscriber count is below 500,000."

Use this as the **definition from the training material**. For a real
implementation, always verify current Salesforce limits and account
capabilities because Marketing Cloud features and limits can change.

### 2. Soft-bounce retry numbers

The screenshot says:

> "Marketing Cloud tries to resend the email every 15 minutes for 72
> hours, i.e., 288 times."

This is useful for understanding the training example, but do not
memorize it as a universal current-platform rule. Verify current
Salesforce bounce-management behavior before using it in a production
design.

### 3. Three soft bounces in 15 days

The screenshot says:

> "3 soft bounces in a span of 15 days will result into Hard Bounce."

Treat this as the **course material's rule/example**. Current
subscriber-status behavior should be validated against the current
Salesforce documentation and your account configuration.

### 4. CAN-SPAM "10 days"

The screenshot says:

> "You must process an unsubscribe request within 10 days."

The current FTC guidance specifies **10 business days**.

### 5. CAN-SPAM is a U.S. law

CAN-SPAM is a U.S. law. Other regions may have additional or different
privacy/marketing requirements, such as GDPR in the European Union or
other local electronic-marketing laws.
