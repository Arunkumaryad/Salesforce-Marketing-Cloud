# 1. Send Classifications

## Definition

> **A send classification categorizes a send as either commercial or transactional.**

A Send Classification is used to define how a send is classified and associates a **Sender Profile** and **Delivery Profile** with the send.

## Commercial

Commercial messages are marketing/promotional communications.

### Examples from the training material
- Promotional emails
- Newsletter emails

Commercial emails normally include the appropriate unsubscribe/preference-management mechanism.

## Transactional

Transactional messages are sent because a customer needs a specific account or transaction-related communication.

### Examples from the training material
- A `"forgot my password"` email for a customer account. The customer needs it, and that need triggers the message regardless of newsletter subscription.
- A `"Double Opt-in Confirmation Request"` email when the user demonstrably wants to re-subscribe and the message is required to complete that transaction.

### Important Interview Point

A transactional message should be genuinely transaction/account related. It should not be used simply to bypass marketing consent requirements.

# 2. Sender Profile

## Definition

> **A sender profile specifies the from information that displays in the recipient's inbox.**

The screenshot/training example shows:

```text
Sender Profile | CU Connections <connections@cu.edu>
    From Name  | CU Connections
    From Email | connections@cu.edu
```

## Purpose

The Sender Profile controls the sender identity, primarily:

- From Name
- From Email
- Reply information, where configured

### Easy way to remember

```text
Sender Profile = Who is sending the email?
```

Example:

```text
From Name:  CU Connections
From Email: connections@cu.edu
```

# 3. Delivery Profile

## Definition

> **A delivery profile specifies if the communication is Commercial or Transactional in nature.**

The training material also states:

> **Commercial messages use the FOOTER FOR ALL EMAILS delivery profile that allows constituents to "manage my email preferences".**

And:

> **Transactional messages do not give constituents an option to unsubscribe and is used in special circumstances only.**

### Example from the training material

```text
Delivery Profile | CU FOOTER FOR ALL EMAILS
```

It is described as:

- Mainly used for commercial messages.
- Also provides a feature to pick IPs available in the system.

### Easy comparison

| Sender Profile | Delivery Profile |
|---|---|
| Defines sender identity | Defines delivery-related configuration |
| From Name | Delivery settings |
| From Email | Footer/preference behavior can be associated |
| Answers: "Who is sending?" | Answers: "How is this send delivered/classified?" |

> **Note:** In current SFMC implementations, the exact commercial/transactional configuration and compliance behavior can depend on the account setup and sending configuration. Always follow your organization's compliance requirements.

# 4. Personalization Strings

## Definition

> **The Marketing Cloud processes each personalization string individually for each subscriber at the time of sending the email.**

The training material says these strings are used extensively to include values from:

- System attributes
- Data Extension attributes


# 5. AMPscript

## Definition

**AMPscript is Salesforce Marketing Cloud's scripting language for creating personalized and dynamic content in emails and other supported Marketing Cloud experiences.**

AMPscript can:

- Retrieve Data Extension data.
- Create and assign variables.
- Apply conditions.
- Perform calculations.
- Format data.
- Generate dynamic content.
- Handle fallback values.
- Personalize email content.

## AMPscript Block

```ampscript
%%[
VAR @FirstName
SET @FirstName = "Arun"
]%%
```

Display the variable:

```ampscript
%%=v(@FirstName)=%%
```

Result:

```text
Arun
```

## Common AMPscript Structure

```ampscript
%%[
/* AMPscript statements */
SET @name = "Arun"
]%%

Hello %%=v(@name)=%%!
```

# 6. Personalization Strings vs AMPscript

| Personalization Strings | AMPscript |
|---|---|
| Simple personalization | Advanced/dynamic personalization |
| Easy field substitution | Supports logic and data retrieval |
| Example: `%%FirstName%%` | Example: `%%=v(@FirstName)=%%` |
| Good for straightforward attributes | Good for Data Extension lookups |
| Limited logic | Supports IF/ELSE, variables, functions, etc. |

### When to use Personalization Strings

Use them when you simply need to display a known attribute:

```text
Hello %%FirstName%%
```

### When to use AMPscript

Use AMPscript when you need a process such as:

```text
Subscriber
   ↓
Find transaction
   ↓
Find product
   ↓
Find image
   ↓
Check image
   ↓
Display image or fallback
```

# 10. Dynamic Image and Fallback Logic

The screenshots show logic intended to handle a missing product image.

## Why fallback is needed

If the image URL is empty or invalid, the recipient may see a broken image.

Instead, the email can display:

```text
Image Not Found
```

or a default image.

## Example Fallback Code

```ampscript
%%[
VAR @ImageURL

IF EMPTY(@Image)
   OR @Image == "null"
   OR @Image == "undefined"
THEN

    SET @ImageURL = ""

ELSE

    SET @ImageURL = @Image

ENDIF
]%%
```

Then:

```ampscript
%%[
IF NOT EMPTY(@ImageURL) THEN
]%%

<img src="%%=v(@ImageURL)=%%"
     alt="Product Image"
     width="250">

%%[
ELSE
]%%

<p>Image Not Found</p>

%%[
ENDIF
]%%
```

### Logic

```text
Image exists?
   |
   +--- YES ---> Display product image
   |
   +--- NO ----> Display fallback
```

### Important improvement

In a production email, it is often better to use a real default image URL rather than only text:

```ampscript
SET @DefaultImage = "https://example.com/images/default-product.jpg"
```

Then:

```ampscript
IF EMPTY(@Image) THEN
    SET @ImageURL = @DefaultImage
ELSE
    SET @ImageURL = @Image
ENDIF
```

# 13. Common Errors

## Error 1 — Wrong Data Extension Name

If the actual DE is:

```text
TransactionData_Arun
```

do not use:

```text
TransactionData
```

Use the exact name/key required by your implementation.

## Error 2 — Wrong Field Name

If the field is:

```text
SubscriberKey
```

do not assume it is:

```text
Subscriber_Key
```

Field names must match.

## Error 3 — No Matching Record

If the subscriber does not exist in the transaction DE, a lookup can return an empty result.

Check:

```text
SubscriberKey
```

in the test data.

## Error 4 — Product Does Not Match

Transaction DE:

```text
Product = Dell Laptop
```

Product DE:

```text
ProductName = Laptop
```

These values do not match, so the product lookup may return empty.

## Error 5 — Broken Image

A value such as:

```text
image.jpg
```

is not necessarily a usable image URL.

Prefer a valid accessible URL such as:

```text
https://example.com/images/product.jpg
```

## Error 6 — AMPscript Appears as Raw Text

During editing, you may see:

```text
%%=v(@bill)=%%
```

instead of a value.

Use **Preview and Test** with a valid subscriber/test record. The Content Builder editor itself is not the same as final send-time rendering.

## Error 7 — Multiple Transactions

If one subscriber has multiple transactions, a lookup only by `SubscriberKey` may not uniquely identify the correct purchase.

Use an appropriate unique key such as:

```text
TransactionID
```

or:

```text
OrderID
```

# 14. Important AMPscript Functions

## VAR

Declares variables:

```ampscript
VAR @name, @email
```

## SET

Assigns a value:

```ampscript
SET @name = "Arun"
```

## v()

Outputs a variable:

```ampscript
%%=v(@name)=%%
```

## Lookup()

Returns a value from a Data Extension:

```ampscript
Lookup(
    "DataExtensionName",
    "ReturnField",
    "SearchField",
    "SearchValue"
)
```

## LookupRows()

Returns multiple matching rows:

```ampscript
SET @rows = LookupRows(
    "TransactionData_Arun",
    "SubscriberKey",
    @subkey
)
```

## Row()

Gets a particular row:

```ampscript
SET @row = Row(@rows, 1)
```

## Field()

Gets a field from a row:

```ampscript
SET @product = Field(@row, "Product")
```

## Empty()

Checks whether a value is empty:

```ampscript
IF EMPTY(@Image) THEN
```

## IF / ELSE / ENDIF

Conditional logic:

```ampscript
IF @bill > 50000 THEN

    SET @message = "VIP Purchase"

ELSE

    SET @message = "Thank you for your purchase!"

ENDIF
```

## Concat()

Combines strings:

```ampscript
SET @fullName = Concat(@firstName, " ", @lastName)
```

## FormatDate()

Formats dates:

```ampscript
SET @formattedDate = FormatDate(@date, "dd/MM/yyyy")
```

# 15. Interview Questions

## Q1. What is a Personalization String?

**Answer:**

A Personalization String is a dynamic placeholder that Marketing Cloud replaces with subscriber-specific data. It can be used with profile attributes, system attributes and supported Data Extension attributes.

Example:

```text
Hello %%FirstName%%
```

---

## Q2. What is AMPscript?

**Answer:**

AMPscript is Salesforce Marketing Cloud's scripting language used to create dynamic, personalized and data-driven content. It can retrieve Data Extension values, use variables, perform calculations, apply conditions and control dynamic content.

---

## Q3. What is the difference between Personalization Strings and AMPscript?

**Answer:**

Personalization Strings are mainly used for simple value substitution. AMPscript is more powerful and is used when the email needs lookups, variables, conditions, calculations, formatting or dynamic content.

---

## Q4. What is a Sender Profile?

**Answer:**

A Sender Profile specifies the From information displayed in the recipient's inbox, such as From Name and From Email.

---

## Q5. What is a Delivery Profile?

**Answer:**

A Delivery Profile specifies delivery-related settings and is associated with how a send is delivered. The training material describes it in relation to commercial and transactional communication.

---

## Q6. What is a Send Classification?

**Answer:**

A Send Classification categorizes a send as commercial or transactional and associates a Sender Profile and Delivery Profile with the send.

---

## Q7. What is Lookup()?

**Answer:**

`Lookup()` retrieves a field value from a Data Extension using one or more search criteria.

Example:

```ampscript
SET @product = Lookup(
    "TransactionData_Arun",
    "Product",
    "SubscriberKey",
    @subkey
)
```

---

## Q8. What is LookupRows()?

**Answer:**

`LookupRows()` returns a rowset containing multiple records that match the search criteria.

---

## Q9. Difference between Lookup() and LookupRows()?

**Answer:**

`Lookup()` is used when you want a value from a matching record. `LookupRows()` returns multiple matching rows as a rowset that can be processed further.

---

## Q10. What does v() do?

**Answer:**

`v()` outputs the value stored in an AMPscript variable.

```ampscript
%%=v(@product)=%%
```

---

## Q11. Why use IF/ELSE?

**Answer:**

To show different content based on a condition.

Example:

```ampscript
IF EMPTY(@Image) THEN
    /* fallback */
ELSE
    /* image */
ENDIF
```

---

## Q12. How do you handle missing data?

**Answer:**

Use `EMPTY()` and conditional logic to provide fallback content.

---

## Q13. Can AMPscript retrieve Data Extension data?

**Answer:**

Yes. Common functions include `Lookup()`, `LookupRows()`, `LookupOrderedRows()`, `Row()` and `Field()`.

---

## Q14. Why might personalization appear as raw text?

**Answer:**

Possible reasons include:

- Looking at the email editor rather than rendered preview.
- No subscriber/test context.
- Incorrect syntax.
- Missing subscriber attribute.
- Incorrect field name.
- Invalid AMPscript.

---

## Q15. What happens when Lookup() finds no matching data?

**Answer:**

The returned value can be empty. The email should use appropriate validation and fallback logic rather than assuming the value exists.
