## 1. Accessing Contact Builder

From the main Salesforce Marketing Cloud landing page, **Contact Builder** is accessed via the **Audience Builder** icon in the top navigation bar (alongside Email Studio, Mobile Studio, Advertising, Web Studio, Personalization, Analytics Builder, Journey Builder, and Content Builder).

Hovering over **Audience Builder** reveals **Contact Builder** as an option.

Once inside, Contact Builder has its own navigation bar:
- **Data Designer**
- **All Contacts**
- **Data Sources**
- **Data Extensions**
- **Imports**
- **Contacts Configuration**

---

## 2. Data Designer & Attribute Groups

**Data Designer** is the visual tool used to model how customer/contact data is structured and connected.

It has two main views:
- **Attribute Groups** — logical groupings of related data (e.g., Email Data, Mobile Data, System Data), each linked back to the central **Contacts** node.
- **Populations** — segments of contacts based on defined criteria.

Each Attribute Group shown in Data Designer displays how many **attributes** it contains — for example:
- MobileConnect Data — 30 Attributes
- GroupConnect (LINE) Data — 20 Attributes
- Email Data — 7 Attributes
- Chat Message Data — 65 Attributes
- MobilePush Data — 47 Attributes
- Predictive Intelligence Data — 93 Attributes
- System Data — 4 Attributes

**In simple words:** Data Designer is like a visual map showing all the different "buckets" of data connected to a Contact — email activity, mobile activity, predictive scores, and more — all radiating out from the central Contacts record.

---

## 3. Creating an Attribute Group

Steps to create a new custom Attribute Group:

1. In **Data Designer**, click **+ Create Attribute Group**.
2. In the **Create New Attribute Group** dialog:
   - Enter a **Name** (e.g., `InvoiceTransactionGroup_Arun`).
   - **Select an Attribute Group Icon** to visually represent the group (options include database, people, dollar, cart, email, mobile, laptop, analytics, travel, location, settings, and building icons).
3. Click **Create**.

Once created, the new Attribute Group starts out **empty**, showing the message *"This attribute group is empty. No attributes or data extensions are created…"* with two options to populate it:
- **Create New Data Extension**
- **Link Data Extensions**

---

## 4. Linking a Data Extension to an Attribute Group

To connect an existing Data Extension to your Attribute Group:

1. Click **Link Data Extensions**.
2. In the **Link Data Extension** dialog, the left panel shows **Customer Data** system-generated fields (Contact Key, Email Address, Mobile Address, Push Device, Push Application, LINE) and **Populations**.
3. On the right panel, browse **Data Extensions** (or **Shared Items**) and select the Data Extension you want to link (e.g., `CustomerProfile_Arun`).
4. Click **Save**.

---

## 5. Mapping Contact Key to Subscriber Key

When linking a Data Extension, you must map the relationship key:

- On the left: **Contact Key** (the universal identifier in Contact Builder).
- On the right: **SubscriberKey** (the primary key field in your Data Extension, e.g., `CustomerProfile_Arun`).
- A **relationship type** dropdown (e.g., **One**) defines the cardinality of the relationship (one Contact relates to one record in this Data Extension).

Other fields available for reference/mapping include: FirstName, LastName, EmailAddress, PhoneNumber, Gender, Age (from the linked Data Extension) and Email Address, Mobile Address, Push Device, Push Application, LINE (system-generated Contact fields).

Once saved, the Data Designer view updates to show the **Contacts** node connected via **Contact Key** to the linked Data Extension node (e.g., `CustomerProfile_Arun`), listing all its fields (SubscriberKey, FirstName, LastName, EmailAddress, PhoneNumber, Gender, Age, Country) and displaying a summary like *"1 attribute sets linked, 8 attributes total."*

**In simple words:** This is the step that actually connects your custom Data Extension table to every Contact record — using Contact Key ↔ Subscriber Key as the "join" between the two, similar to a foreign key relationship in a relational database.

---

## 6. Linking Multiple Data Extensions (Relationships)

Contact Builder allows you to chain multiple Data Extensions together into a relational structure:

- **Contacts → CustomerProfile_Arun → TransactionData_Arun → ProductSpecification_Arun**

Example structure:
| Data Extension | Fields |
|---|---|
| **CustomerProfile_Arun** | SubscriberKey, FirstName, LastName, EmailAddress, PhoneNumber, Gender, Age, Country |
| **TransactionData_Arun** | SubscriberKey, Product, Bill, Quantity, Date |
| **ProductSpecification_Arun** | ProductName, Brand, Color, Size, Image |

As more Data Extensions are linked, the Attribute Group summary updates accordingly (e.g., *"3 attribute sets linked, 18 attributes total"*).

**In simple words:** This is how Marketing Cloud builds a **relational data model** — a Contact links to a Customer Profile, which links to their Transactions, which links to Product details — letting you build rich, connected customer views (e.g., "show me all products purchased by this customer, with product specs") instead of one flat table.

## 7. Email Studio

**Definition:** Email Studio is used to create various types of email communications:

- **Promotional emails:** newsletters, promotions, flash sales, loyalty programs, events, and coupons.
- **Transactional and triggered emails:** hotel reservations, purchase confirmations, shipping notifications, overdraft alerts, and bank statements.
- **E-commerce emails:** abandoned shopping cart emails, order confirmations, next best offer recommendations, and receipts.

**In simple words:** Email Studio is Marketing Cloud's dedicated tool for designing, sending, and tracking all types of emails — from marketing campaigns to automated transactional messages triggered by customer actions.

---

## 8. Email Studio Lists

**Definition:** Lists in Email Studio have these characteristics:

- **Lists are a default method of storing data** in Marketing Cloud Email Studio.
- **You can set different attributes to your subscribers** using lists, which represent a collection of subscribers.
- **You can only use lists if your subscriber count is below 500,000.**
- **Lists work best to manage a relatively simple subscriber model** that doesn't contain other commercial or transactional information.

**In simple words:** Lists are the simplest, built-in way to manage subscribers in Email Studio — ideal for straightforward use cases, but not designed for complex data like purchase history or product details (that's what Data Extensions/Contact Builder are for).

---

## 9. Subscriber Key

**Definition:**
- **In Email Studio, contacts are identified by the Subscriber Key**, which becomes the **Contact Key** in Contact Builder.
- **The Subscriber Key is the primary key** for your subscribers and allows you to identify subscribers with a value that you choose.

**In simple words:** Subscriber Key and Contact Key refer to the same underlying identifier — just named differently depending on which tool you're working in (Email Studio vs. Contact Builder). It's the unique "ID" that ties a person's records together across the platform.

---

## 10. All Subscriber List

**Definition:**
- **The All-Subscribers list is considered the master list of records** for the Marketing Cloud Email Studio account.
- **Every subscriber in your account appears in the All-Subscribers list.** Subscribers added to a subscriber list join the All-Subscribers list at the same time.
- **Subscribers stored on data extensions join the All-Subscribers list when you send your first message** to that subscriber.

**In simple words:** Think of the All-Subscribers list as the master roster of every person Marketing Cloud has ever sent to or tracked — whether they came from a List or a Data Extension, they eventually show up here, either immediately (Lists) or upon their first send (Data Extensions).

The **Subscribers** dropdown menu (in Email Studio) includes: All Subscribers, Lists, Groups, Profile Management, Preference Management, Data Extensions, Salesforce Data Extensions, Shared Data Extensions, Shared Salesforce Data Extensions, Data Relationships, Publication Lists, Shared Publication Lists, Suppression Lists, Shared Suppression Lists, Data Filters, and Measures.

## 11. Data Extension Sending Relationship (Example)

A Data Extension's **Properties** tab shows how it relates to sending, for example on `CustomerProfile_Arun`:

- **Type:** Sendable
- **Used For Sending:** Yes
- **Used For Testing:** Yes
- **Subscriber Relationship:** *SubscriberKey relates to subscriber on Subscriber Key*
- **Records:** 10 (with a **Last Refreshed** timestamp)
- **Attributes** list: SubscriberKey, FirstName, LastName, EmailAddress, PhoneNumber, Gender, Age — each with Default Value, Length, and Nullable settings, plus **Create Attribute**, **Export**, and **Import** actions available.

**In simple words:** Marking a Data Extension as "Sendable" and defining its Subscriber Relationship is what allows Marketing Cloud to actually use that Data Extension as a source for sending emails — connecting its records to real subscribers via the Subscriber Key.

### Quick-Fire Definitions
- **Contact Builder** → Tool for designing and managing how contact/customer data is structured and connected across Marketing Cloud.
- **Attribute Group** → A logical grouping of related data attributes linked to Contacts.
- **Contact Key** → The universal identifier for a Contact in Contact Builder (same as Subscriber Key in Email Studio).
- **Subscriber Key** → The primary key identifying a subscriber in Email Studio.
- **All-Subscribers List** → The master list containing every subscriber in the Marketing Cloud account.
- **Sendable Data Extension** → A Data Extension configured with a Subscriber Relationship so it can be used to send messages.
