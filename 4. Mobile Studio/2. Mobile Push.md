# 2. What is MobilePush?

### Definition from the screenshot

> **"Marketing Cloud MobilePush lets you create and send notifications
> to encourage use of your app."**

### Easy Explanation

**MobilePush** allows Salesforce Marketing Cloud Engagement to send push
notifications to users of a mobile application.

For example:

> "Hi Arun, your order has been shipped. Track it now."

The notification can appear on the user's mobile device even when the
user is not actively using the application, depending on the
notification type and device settings.

### Common MobilePush Use Cases

-   Order/shipping notifications
-   Appointment reminders
-   New product announcements
-   Promotional offers
-   Cart reminders
-   Account/security notifications
-   App engagement
-   Personalized recommendations
-   Location-based notifications
-   Re-engagement campaigns

# 3. MobilePush Architecture

A simple way to understand MobilePush is:

``` text
Mobile Application
       |
       | MobilePush SDK
       v
Marketing Cloud Engagement
       |
       +--> MobilePush App Configuration
       |
       +--> Audience / Contacts
       |
       +--> Push Message
       |
       +--> Journey Builder / API / Mobile Studio
       |
       v
FCM / APNs
       |
       v
Customer Mobile Device
```

### Important Components

1.  **Mobile Application**
    -   The Android or iOS application receiving the push notification.
2.  **MobilePush SDK**
    -   Connects the mobile application with Marketing Cloud Engagement.
    -   Allows Marketing Cloud to register and communicate with app
        users.
3.  **MobilePush App**
    -   Created inside Marketing Cloud.
    -   Contains configuration information required to connect the
        application.
4.  **Audience**
    -   The contacts/devices that can receive messages.
5.  **Push Message**
    -   The notification sent to the selected audience.
6.  **APNs / FCM**
    -   Apple Push Notification service (APNs) is used for Apple
        devices.
    -   Firebase Cloud Messaging (FCM) is used for Android messaging.

# 4. Prerequisites for MobilePush

Before sending push notifications, both the **app developer** and the
**Marketing Cloud marketer/admin** have work to complete.

## 4.1 App Developer Prerequisites

The app developer needs to:

1.  Prepare the Android and/or iOS application.
2.  Integrate the current Salesforce MobilePush SDK.
3.  Configure the application for push notifications.
4.  Create/provision the required Apple and Google push services.
5.  Connect the application to the MobilePush app configuration.
6.  Test device registration and notification delivery.

### Important MobilePush Configuration Values

The MobilePush app provides configuration information such as:

-   App ID
-   Access Token
-   App Endpoint
-   MID/account information

These values are used by the mobile application configuration.

------------------------------------------------------------------------

## 4.2 Marketer/Admin Prerequisites

The Marketing Cloud admin/marketer needs to:

1.  Create the MobilePush app.
2.  Configure the app.
3.  Create/import an audience.
4.  Confirm contacts/devices are registered.
5.  Create a push message.
6.  Select the audience.
7.  Personalize the message if required.
8.  Test the notification.
9.  Schedule/send/activate it.

# 6. MobilePush SDK

The **MobilePush SDK** is the software component integrated into the
mobile application so that the application can communicate with
Marketing Cloud Engagement.

### Easy Explanation

Without the SDK integration, Marketing Cloud does not have the required
application-side connection for MobilePush functionality.

### Typical Flow

``` text
User installs app
      ↓
User opens app
      ↓
MobilePush SDK initializes
      ↓
Device/contact information is registered
      ↓
User enables notifications
      ↓
Contact becomes eligible
      ↓
Marketing Cloud sends Push
      ↓
Device receives notification
```

# 7. MobilePush Audience

### Definition

A **MobilePush audience** is a group of contacts that you can send a
notification or message to.

### Easy Explanation

An audience answers:

> **"Who should receive this push notification?"**

### Audience Options

Depending on the implementation, you can work with:

-   Imported contacts
-   Filtered lists
-   Data Extension-based audiences
-   Contact/device data

### Example

Suppose you have:

``` text
10,000 App Users
```

You can create an audience:

``` text
Customers who purchased in the last 30 days
```

Only those contacts are targeted.

# 8. Opt-In and Opt-Out

Push notifications depend on the user's device/app notification
permission and MobilePush contact eligibility.

### Opt-In

A user can become eligible to receive push notifications after:

1.  Installing/opening the application.
2.  Registering through the MobilePush SDK.
3.  Enabling notifications where required.

### Opt-Out

A user can become ineligible when, for example:

-   The user disables notifications for the app.
-   The user removes the application.
-   The device/application is no longer eligible.

### Important Interview Point

Do not assume:

> "Every person who installed the app can receive a push."

Device registration, notification permission, contact status, and app
configuration all matter.

An Inbox Message is different from a standard push alert.

### Easy Explanation

``` text

      ↓

      ↓
```

An in-app message is displayed while the customer is using the mobile

# 23. MobilePush Contact and Device Concept

A very important interview topic is the difference between a **contact**
and a **device**.

### Contact

Represents the customer/person that Marketing Cloud is communicating
with.

Example:

``` text
ContactKey = C001
```

### Device

Represents an application installation/device associated with the
contact.

Example:

``` text
Contact
   |
   +---- Device 1
   |
   +---- Device 2
```

A single contact can have multiple eligible devices depending on the
implementation.

3.  Register a test device.
4.  Enable notifications.
5.  Verify the device/contact appears correctly.

9.  Confirm:
    -   Notification received

# 29. Related Training Screenshot -- SMS vs MMS

### SMS Definition from the screenshot

> **"SMS stands for Short Message Service."**

The screenshot describes SMS as text-only and typically limited to 160
characters.

### MMS Definition from the screenshot

> **"MMS stands for Multimedia Messaging Service."**

The screenshot says MMS messages can include:

-   Images
-   Sound
-   Video

### Easy Comparison

  SMS                            MMS
  ------------------------------ ---------------------------------------
  Short Message Service          Multimedia Messaging Service
  Primarily text                 Multimedia supported
  Commonly used for alerts/OTP   Useful for richer media communication

> The traditional 160-character statement can vary with encoding and
> carrier/message segmentation, so do not treat 160 as an absolute limit
> for every SMS.

> **Note:**
>
> 1.  Mobile SMS does **not** support multimedia (no images, audio, or
>     video -- for multimedia content, MMS must be used instead).
> 2.  A single SMS can store only **160 characters**. If the message
>     content is more than 160 characters, it is automatically split and
>     sent as **another SMS** (multi-part/segmented SMS).

Thinking MobilePush is the same as SMS.

**Correct:**

``` text
MobilePush → App notification
MobileConnect → SMS/MMS
```

### Mistake 2

Creating a push before configuring the mobile application.

### Mistake 3

Ignoring device notification permission.

### Mistake 4

Testing only from the marketer side and not testing the actual mobile
device.

### Mistake 5

Ignoring platform-specific behavior.

### Mistake 6

Putting too much content into the push payload.

### Mistake 7

Not testing personalization.

### Mistake 8

Assuming a push send time means every device receives the notification
at exactly that time.

# 45. Best Practices

1.  Always test with a small audience first.
2.  Use meaningful message names.
3.  Keep push content concise.
4.  Personalize where it provides value.
5.  Use deep links to send customers to the correct app screen.
6.  Respect notification permissions and customer preferences.
7.  Validate Android and iOS behavior separately.
8.  Test rich media on real devices.
9.  Monitor delivery and engagement.
10. Keep SDK/configuration versions aligned with Salesforce-supported
    requirements.
11. Use segmentation to avoid irrelevant notifications.
12. Do not over-send push notifications.

# 51. Step-by-Step Walkthrough (From Actual Product Screenshots)

This section documents the **real MobilePush workflow** captured directly
from Salesforce Marketing Cloud Engagement screenshots -- from creating a
MobilePush app, to building a push notification in Content Builder, to
setting up a geofence Location, and finally creating a Location-Entry
triggered message from the MobilePush Overview screen.

Each part below is broken into **clear numbered steps with the exact
example values shown on screen**, so it can be followed like a hands-on
lab guide.

------------------------------------------------------------------------

## 51.1 Create a New MobilePush App (Administration)

**Where:** `MobilePush → Administration`

### Steps

1.  Open the **MobilePush** app and click the **Administration** tab.
2.  On the Administration page you can see:
    -   **Settings** -- Rich Media (Enabled/Disabled), Send Blockout
        (Enabled/Disabled).
    -   **Stored Content** -- Headers and Footers (reusable content
        blocks added to every push, up to 3 each).
    -   **Subscription Term** -- the start/end date of the MobilePush
        license period.
    -   **Apps** grid -- lists every MobilePush app already created,
        with **App**, **App ID**, **Access Token**, **Active Users**,
        **Modified Date**, and **Actions** columns.
3.  Click **+ Create New App** (top-right corner) to start a new app.
4.  In the **New App** popup, enter:
    -   **Name\*** (required) -- Example: `InvoiceTransactionApp_Arun`
    -   **Description** (optional) -- free text describing the app.
5.  Click **Save**.
6.  Marketing Cloud creates the app and opens the **App Details and SDK
    Configuration** page, where you can see the system-generated values:
    -   **Access Token** -- Example: `hMFsdA29F0THRjYohM5Sc5U8`
    -   **App ID** -- Example: `10345de0-7290-43d3-863b-92b1d875ebce`
    -   **App Endpoint** -- Example:
        `https://mc7k8jp2431nbqcs5w-p4d8mr62q.device.marketingcloudapis.com/`
7.  On the same page you can optionally:
    -   Upload a **Mobile Push Icon** (PNG, minimum 18x18 px, maximum
        200x200 px, maximum file size 500 KB).
    -   Configure **iOS Sending** under *Sending Services*:
        -   Choose **Production** or **Development**.
        -   Upload the **APNs .p8 Auth Key** (Key ID, Team ID, Bundle
            ID) -- Apple recommends the .p8 key over the legacy .p12
            certificate.
    -   Configure **Android Sending**:
        -   Upload the **Firebase Config File (Service Account JSON)**
            provided by the Firebase Developer Console.
    -   Both iOS Sending and Android Sending show **Disabled** until a
        valid certificate/key or Firebase file is uploaded.
8.  Click **Save** (top-right) to save the app configuration.

> **Tip:** The **App ID**, **Access Token**, and **App Endpoint** are the
> three values the mobile app developer needs to complete the MobilePush
> SDK integration inside the Android/iOS application.

------------------------------------------------------------------------

## 51.2 Create a Push Notification in Content Builder

**Where:** `App Switcher → Content Builder`

### Steps

1.  From anywhere in Marketing Cloud, open the **App Switcher** (grid of
    apps: Email Studio, Mobile Studio, Advertising, Web Studio,
    Personalization, Analytics Builder, Journey Builder, **Content
    Builder**, Audience Builder, Einstein, AppExchange, Platform, Next).
2.  Click **Content Builder**.
3.  On the **Content Builder → Overview** page you see the full content
    library (folders on the left, content items in a grid with **Name**,
    **Location**, **Type**, and **Customer Key** columns).
4.  Click **+ Create** (top-right) to open the content-type menu.
5.  Hover over **Mobile App**, then select **Push Notification** (other
    options in the same menu are **In-App Message**, **Chat Messaging**,
    and **Upload**).
6.  On the **Select a Layout** screen choose one of:
    -   **Standard** -- create a push notification with **1 media
        attachment**.
    -   **Carousel** -- create a push notification with **up to 6
        images**, compatible with SDK versions 9.x and newer.
7.  A live **iPhone Lock Screen** preview is shown on the right as you
    build the notification (device type and screen dropdowns, plus a
    byte-usage counter, e.g. *137 of 4096 bytes used*).
8.  Click **Next** to move to the content editor.

------------------------------------------------------------------------

## 51.3 Build the Push Content and Personalize It

**Where:** `Content Builder → (new push) → Content tab`

### Steps

1.  On the **Content** tab, fill in the push fields (each has a **Show**
    toggle so you can include/exclude it):
    -   **Title** -- Example: `Amazon Invoice`
    -   **Subtitle** -- Example:
        `Hii %%FirstName%%, Thank You For Purchasing With...`
    -   **Message** -- free text/AMPscript block, Example:
        ``` text
        %%[
        var @subkey, @product, @bill, @quantity,
        @date, @brand, @color, @size
        ...
        ]%%
        ```
2.  Personalization icons (a person icon and a smiley icon) next to each
    field let you insert **personalization strings** (e.g.
    `%%FirstName%%`) or **emojis** directly into Title/Subtitle/Message.
3.  The **iPhone Lock Screen** preview on the right updates live as you
    type, and shows a **byte counter** so you can track the 4096-byte
    payload limit.
4.  Click **Subscriber Preview** (top toolbar) to test the message with
    real subscriber data.
5.  On the **Subscriber Preview** screen:
    -   Confirm the **Subscriber Source** (Example: `CustomerProfile_Arun`
        Data Extension).
    -   Optionally choose an **App** to preview against.
    -   Pick a subscriber row from the grid (Example:
        `B36DEsubkey01 | Arun | Kumar | arun@sraban.com`).
    -   The right-hand phone preview renders the **merged, personalized**
        notification -- Example: *"Amazon Invoice / Hii Arun, Thank You
        For Purchasing With... / Product : Bag..."*.
6.  Click **Return to Editor** to go back, then **Validate** (bottom of
    the panel) to check the message for errors.
7.  Click **Save** to save the push notification content.

------------------------------------------------------------------------

## 51.4 Create a Geofence Location

**Where:** `MobilePush → Location`

### Steps

1.  Click the **Location** tab in MobilePush.
2.  The **Locations** page shows a world map with pins for every saved
    location, a search box, a location list (Name, Address, Coordinates,
    "Contacts Here in Last 24 Hours", Last Modified), and a counter such
    as *2 of 25 Locations Available*.
3.  Click **+ Create Location**.
4.  In the **Create Location** popup, choose the location type:
    -   **Geofence** -- set up a GPS geofence perimeter to trigger
        message sends or collect data.
    -   **Beacon** -- set up a low-energy Bluetooth beacon perimeter to
        trigger message sends or collect data.
5.  Select **Geofence**.
6.  In the search box, search for a place, enter an address, or click
    directly on the map to drop a marker -- Example search:
    `McDonald's - Kalkaji, Delhi, Main Road`.
7.  A map info-window appears with the matched place name and full
    address (Example: *McDonald's - Kalkaji, Delhi -- 12A, Main Rd, near
    DESHBANDHU COLLEGE, Block H, Kalkaji, New Delhi, Delhi 110019,
    India*). Click **Select**.
8.  The location moves into the **Selected** panel on the right, showing:
    -   **Coordinates** (Example: `28.540237, 77.257776`)
    -   **Location Label\*** (editable, defaults to the place name)
    -   **Description** (editable, defaults to the full address)
    -   **Geofence Radius\*** in meters (Example: `100`) -- a blue
        circle on the map visually shows this radius around the pin.
9.  Adjust the **Geofence Radius** if needed, then click **Save**
    (bottom-right).
10. The new location is added to the Locations list (the *"X of 25
    Locations Available"* counter increases).

------------------------------------------------------------------------

## 51.5 Save a Location-Triggered Push Message

**Where:** `Content Builder → (push message linked to a location)`

### Steps

1.  In the push message content editor, set the **Title**, **Subtitle**,
    and **Message** for the location-based notification -- Example:
    -   **Title:** `Welcome to MCD`
    -   **Subtitle:** `Grab 20% Discount Now.`
    -   **Message:** `Visit the store just 100 Meters Away.`
2.  Review the live **iPhone Lock Screen** preview and the byte counter
    (Example: *244 of 4096 bytes used*).
3.  Click **Save** (top-right) once the content is finalized -- the
    **Unsaved changes** warning clears after saving.

------------------------------------------------------------------------

## 51.6 Create a Location Entry Message (Trigger a Send on Geofence Entry)

**Where:** `MobilePush → Overview → Create Message`

### Steps

1.  Go to **MobilePush → Overview**. This dashboard shows:
    -   **Message Analytics** (Delivered / Opened counts, with a date
        range filter such as *Last Month*).
    -   **Active Apps** (App name, Avg. Time in App, Push Opt-ins).
    -   **Contacts** (Push Opt-ins, Growth over last 30 days).
    -   **Messages** grid (Name, Message Type, Status, App, Send
        Schedule, Campaign, Activity) with a **View by Status** filter
        (Example: *Active/Scheduled (104)*).
2.  Click **+ Create Message** (top-right).
3.  On the **Create Message** wizard, the top shows 5 stages:
    **Select Template → Define Properties → Select Locations/Audience →
    Define Content → Review and Send**.
4.  On **Select Template**, choose a template type:
    -   **Outbound** -- a standard, non-location push.
    -   **Location Entry** -- trigger a message send when a mobile
        device **enters** a geofenced location.
    -   **Location Exit** -- trigger a message send when a device
        **leaves** a geofenced location.
    -   **Beacon** -- trigger a message using Bluetooth beacon
        proximity.
    -   **Inbox** -- create a message that is retrieved from the app's
        in-app inbox.
5.  Select **Location Entry**, then click **Next**.
6.  On **Define Properties**, fill in:
    -   **Message Name\*** -- Example: `MCDPushNotification_Arun`
    -   **App\*** -- select the MobilePush app to send from, Example:
        `B36AppSirisha`
    -   **Push Method:**
        -   **Alert** -- send a text-only alert to the mobile app.
        -   **Alert + CloudPage** -- send an alert that also directs the
            customer to a mobile-optimized CloudPage/site.
    -   The right-hand panel shows an **Example Use Case**: *"Welcome
        customers to a location and provide special offers. Use
        AMPscript to tell customers about available rewards."*
7.  Click **Next** and continue through **Select Locations** (choose the
    geofence location(s) created in section 51.4, e.g. *McDonald's -
    Kalkaji, Delhi*), **Define Content** (choose/build the push content
    from section 51.3/51.5), and finally **Review and Send** to activate
    the location-triggered message.

# 52. Quick Reference -- Important Notes

> **Note:**
>
> 1.  Mobile SMS does **not** support multimedia.
> 2.  A single SMS stores only **160 characters** -- if the content is
>     more than 160 characters, the remaining text is sent as
>     **another SMS**.

Additional quick notes from the walkthrough in Section 51:

-   A MobilePush app's **iOS Sending** and **Android Sending** stay
    **Disabled** until a valid APNs key/certificate or Firebase config
    file is uploaded and saved.
-   The **Standard** push layout supports **1 media attachment**; the
    **Carousel** layout supports **up to 6 images** and requires SDK
    version 9.x or newer.
-   A push notification payload is limited to **4096 bytes** (shown live
    as a byte counter while editing content).
-   **Location Entry** sends a message when a device **enters** a
    geofence/beacon; **Location Exit** sends a message when a device
    **leaves** it.
-   **Alert** push method is text-only; **Alert + CloudPage** also opens
    a mobile-optimized landing page.
