# 3. A/B Testing

### Definition shown in the screenshot

> "A/B Testing is a market testing method in which you send two versions
> of your Marketing Cloud Email Studio communication to two test
> audiences from your subscriber list."

> "Track which version receives the highest unique open rate or highest
> click-through rate and send that version to all remaining
> subscribers."

### Easy explanation

A/B testing compares two versions of a marketing email. A portion of the
audience receives Version A, another portion receives Version B, and the
system compares performance.

Example:

``` text
10 subscribers
      |
      v
A/B Test
 |          |
30%        30%
 |          |
A          B
 |          |
 -----------
     |
  Results
     |
 Winner
     |
 Remaining 40%
```

Salesforce documents these common A/B test types:

-   Subject Line
-   Email
-   Content Area
-   From Name
-   Send Time
-   Preheader

# 23. Keywords

### Definition shown in the screenshot — "What's a keyword?"

> "A keyword is the word that a subscriber texts to your short code to,
> for example, sign up for your program, get help, and opt-out."

> "You have to set up keywords in Marketing Cloud so that the system
> knows how to respond when it receives a message from a subscriber that
> contains this word."

> "Keywords created at a business unit level, whether parent or child,
> remain available only to that business unit."

### Easy explanation

Keywords are important for two-way MobileConnect communication. A
keyword is simply the trigger word that, when texted to your
short/long code, causes MobileConnect to run a specific configured
response.

``` text
Customer
   |
   | JOIN
   v
Keyword
   |
   v
MobileConnect
   |
   v
Configured response
```

Example response:

``` text
Welcome! You are now subscribed.
```

Keywords can be configured in MobileConnect Administration, and each
keyword created at a business unit level (parent or child) is only
available/usable within that specific business unit — a child business
unit cannot use a keyword created in a different, unrelated business
unit.

### Step-by-step example — Setting up and using a keyword

**Scenario:** A retailer wants subscribers to text `JOIN` to short code
`12345` to sign up for SMS promotions.

| Step | Action | Result |
|---|---|---|
| 1 | Go to **Mobile Studio → MobileConnect → Administration → Keywords**. | Keywords configuration screen opens. |
| 2 | Click **Create Keyword** and enter `JOIN` as the keyword text. | A new keyword record is started. |
| 3 | Assign the keyword to the short code `12345` and to the correct business unit. | The keyword is scoped to that code/business unit only. |
| 4 | Set the keyword type (e.g. **Auto Reply**) and configure the response message: `"Welcome! You are now subscribed."` | MobileConnect knows how to respond to `JOIN`. |
| 5 | Save the keyword. | The keyword is now active. |
| 6 | A subscriber texts `JOIN` to `12345`. | MobileConnect matches the incoming message to the configured keyword. |
| 7 | MobileConnect automatically sends the configured Auto Reply. | Subscriber receives `"Welcome! You are now subscribed."` and is opted in. |

# 23A. STOP Keywords

### Definition shown in the screenshot

> "Mobile Connect account must have a STOP keyword so that people
> sending messages to or receiving messages from the account can
> unsubscribe."

> "Mobile Connect automatically recognizes some keywords as STOP
> keywords."

The screenshot lists the default **Global STOP keywords**:

``` text
STOP
QUIT
CANCEL
END
UNSUBSCRIBE
```

> "These are called as Global STOP keywords and are available by
> default for all codes."

> "If these words occur before the first space in a message, the user
> is immediately unsubscribed from all keywords associated with that
> code."

### Easy explanation

Every MobileConnect account must support at least one STOP keyword so
subscribers can always opt out. Marketing Cloud provides `STOP`,
`QUIT`, `CANCEL`, `END`, and `UNSUBSCRIBE` automatically as Global STOP
keywords for every code — you don't need to configure these yourself.

The key rule is **position in the message**: the STOP word must appear
**before the first space** in the incoming text for it to trigger an
automatic unsubscribe.

### Step-by-step example — STOP keyword behavior

**Scenario:** A subscriber who previously texted `JOIN` to `12345` no
longer wants promotional messages.

| Step | Action | Result |
|---|---|---|
| 1 | Subscriber sends the message `STOP` to short code `12345`. | `STOP` is the first word in the message, before any space. |
| 2 | MobileConnect checks the incoming word against the Global STOP keyword list. | `STOP` matches a Global STOP keyword. |
| 3 | MobileConnect immediately unsubscribes the subscriber. | Subscriber is opted out from **all** keywords associated with code `12345`. |
| 4 | No further keyword-specific configuration is required from the marketer. | Global STOP keywords work automatically, out of the box, for every code. |
| 5 | Compare with a message like `STOP please` vs `Please STOP messaging me`. | Only `STOP please` triggers the automatic unsubscribe, because `STOP` is the first word before the first space; `Please STOP messaging me` does **not** auto-trigger it. |

### Quick memory trick

``` text
STOP keyword rule = STOP word must be BEFORE the first space
Global STOP keywords = STOP, QUIT, CANCEL, END, UNSUBSCRIBE
Available by default = for every short/long code, no setup needed
```

# 31A. Prerequisites to Send SMS

### Definition shown in the screenshot — "What's required to send an SMS?"

> "1. Subscriber Key
> 2. Mobile Number
> 3. Locale (Country)"

### Definition shown in the screenshot — "Sending an SMS to a DE"

> "DE must be sendable
> Contain only one phone field
> Contain only one locale field
> Use subscriber key for the send relationship"

### Easy explanation

To send an SMS at all (to an individual recipient or via a Data
Extension), MobileConnect needs three pieces of information:

``` text
Subscriber Key   → uniquely identifies the recipient
Mobile Number     → where the SMS is delivered
Locale (Country)  → determines number formatting/country rules
```

When the audience comes from a **Data Extension**, that DE has four
additional structural requirements before it can be used as a
MobileConnect send source:

``` text
1. The DE must be marked Sendable
2. The DE must contain exactly ONE phone-type field (not more than one)
3. The DE must contain exactly ONE locale-type field (not more than one)
4. The send relationship must use Subscriber Key (not Subscriber ID)
```

### Step-by-step example — Preparing a Data Extension to send SMS

**Scenario:** A company wants to send an appointment-reminder SMS to
customers stored in a Data Extension called `Appointments_DE`.

| Step | Action | Result |
|---|---|---|
| 1 | Open **Email Studio/Contact Builder → Data Extensions** and select (or create) `Appointments_DE`. | DE properties screen opens. |
| 2 | Confirm required fields exist: `SubscriberKey`, `MobileNumber`, `Locale`, plus any content fields (e.g. `AppointmentDate`). | DE has the three required data points. |
| 3 | In the DE properties, check that only **one** field is typed as a phone field (e.g. `MobileNumber`) — remove or retype any duplicate phone-type fields. | DE contains exactly one phone field. |
| 4 | Check that only **one** field is typed as a locale field (e.g. `Locale`) — remove or retype any duplicate locale-type fields. | DE contains exactly one locale field. |
| 5 | Open **Sendable Data Extension** settings and mark `Appointments_DE` as **Sendable**, choosing `SubscriberKey` as the field used for the subscriber relationship. | DE is now sendable via Subscriber Key. |
| 6 | In MobileConnect, create a **Data Extension Send** and select `Appointments_DE` as the audience. | MobileConnect accepts the DE because all four prerequisites are met. |
| 7 | Send the message, e.g. `"You have an appointment on Tuesday at 9:30 AM. Reply Y to confirm."` | Each recipient receives the SMS at the number/locale stored in their DE row. |

### Quick memory trick

``` text
To send ANY SMS          → Subscriber Key + Mobile Number + Locale
To send via a DE          → Sendable + 1 phone field + 1 locale field + Subscriber Key relationship
```

# 35. Scenario-Based Interview Questions

### Q1. You have 10 subscribers and want to test two subject lines.

**Answer:**

``` text
Create A/B Test
→ Select Subject Lines
→ Select Email
→ Select audience
→ Set 30% / 30% test
→ Keep 40% as remainder
→ Select winner metric
→ Set evaluation period
→ Configure automatic/manual remainder
```

### Q2. You do not want to send SMS from 8 PM to 8 AM.

**Answer:** Configure the MobileConnect Send Blockout window.

### Q3. Salesforce Contact data is needed in Marketing Cloud.

**Answer:** Use Marketing Cloud Connect and a synchronized data source.

### Q4. Can a synchronized data source be the primary sendable DE?

**Answer:** No. Use it as a source and prepare a suitable sendable Data
Extension.

### Q5. What should you use for an app notification?

**Answer:** MobilePush.

### Q6. What should you use for SMS/MMS?

**Answer:** MobileConnect.

### Q7. What is the difference between suppression and exclusion?

**Answer:** Suppression is used to prevent selected subscribers from
receiving communication; exclusion is an audience excluded from a
specific send.

### Q8. How is an A/B winner determined?

**Answer:** According to the selected winner metric, such as higher
unique open rate or higher unique CTR.

### Q9. Why is a remainder audience needed?

**Answer:** The remainder receives the winning version after the test
results are evaluated.

### Q10. Why can SMS character encoding matter?

**Answer:** Non-GSM/Unicode characters can change message segmentation
and the number of SMS segments required.

# 38. Best Practices

## A/B Testing

1.  Test a meaningful variable.
2.  Use a reasonable audience size.
3.  Select one clear winner metric.
4.  Allow enough evaluation time.
5.  Use polished content.
6.  Keep the test audience/data stable.
7.  Review suppression/exclusion settings.
8.  Check tracking after the test.

## MobileConnect

1.  Validate mobile numbers.
2.  Use correct locale information.
3.  Keep SMS content concise.
4.  Consider GSM vs non-GSM characters.
5.  Configure opt-out handling.
6.  Configure keywords where required.
7.  Review blackout windows.
8.  Test before production.
9.  Monitor delivery failures.
10. Use transactional messaging appropriately.
