## 1. Contact Based Data Model

**Definition:** The Contact Based Data Model is built around **Data Extensions**, and has the following key characteristics:

- It **uses Data Extensions** to store and manage customer data.
- A **Data Extension is a custom table within Marketing Cloud, containing the customer data**.
- **Customer information can be linked across Marketing Cloud** and used to **establish relationships with other data extensions**.
- **Data Extensions store multiple pieces of information about a subscriber which cannot be maintained in a List as attributes.**

**In simple words:** Unlike the simpler List model, the Contact Based Data Model uses Data Extensions — which behave like relational database tables. This lets you store far richer, more structured customer data, and link related tables together (e.g., a Customer table linked to an Orders table), which a List alone cannot do.

## 2. Data Types in a Data Extension

Data Extensions support a much wider range of data types than Lists:

| Data Type | Description |
|---|---|
| **Text** | Letters, numbers, and spaces. |
| **Number** | Whole numbers — decimal values are **not supported**. |
| **Date** | A system date. |
| **Boolean** | A 0 or 1 value. |
| **Email Address** | An email address field. |
| **Phone** | A phone number — accepts any string with 10 or 11 digits and strips out non-digit characters. |
| **Decimal** | A number that includes a decimal point. |
| **Locale** | ISO Country & Language codes. |

**In simple words:** Data Extensions offer far more precise field types (e.g., separate Number vs Decimal, dedicated Email/Phone/Locale types) compared to a List's basic Text/Numeric/Date options — making them suitable for structured, validated, relational data.

## 5. Creating a Data Extension

Creating a new Data Extension follows a 3-step wizard: **Properties → Data Retention Policy → Fields**.

1. Go to **Subscribers → Data Extensions**, navigate to the desired folder, and click **Create**.
2. **Properties** — set the Data Extension's name, external key, and description.
3. **Data Retention Policy** — configure how long data should be retained (if applicable).
4. **Fields** — define the table's columns. For each field, specify:
   - **Name** (e.g., ProductName, Brand, Color, Size, Image)
   - **Data Type** (e.g., Text)
   - **Length** (e.g., 50, or 4000 for larger text fields like Image URLs)
   - **Primary Key** (checkbox — marks the field as the unique identifier)
   - **Nullable** (checkbox — whether the field can be left empty)
   - **Default Value**
5. Optionally set a **Send Relationship** — linking the Data Extension to the **Subscribers** list via the **Subscriber Key**, so it can be used for sending.
6. Click **Create** to finish.

**In simple words:** Think of this wizard like designing a spreadsheet/database table — you name your columns, choose their data types, decide which column uniquely identifies each row (Primary Key), and optionally connect the table back to your Subscribers.

## 6. Viewing Data Extension Properties & Fields

Once created, a Data Extension's detail page shows two tabs: **Properties** and **Records**.

**Properties tab** displays:
- **External Key** (a unique GUID identifying the Data Extension)
- **Created Date** / **Last Modified Date** and who made the changes
- **Owner**
- **Location** (which folder it's stored in)
- **Type** (e.g., Standard)
- **Used For Sending** / **Used For Testing** (Yes/No)
- **Subscriber Relationship**
- **Record Count**
- **Fields** table — listing each field's Name, Data Type, Length, Primary Key, Nullable, and Default Value

## 7. Importing Records into a Data Extension

Rather than adding records one at a time, Data Extensions support **bulk import** from a file:

1. Open the Data Extension → **Records** tab.
2. Click **Import**.
3. **Step 1 – Upload File:**
   - Choose **File Location**: *My Computer* or *FTP*.
   - **Browse** and select your file (e.g., `.csv` or `.xlsx`, such as `InvoiceTransactionProject.xlsx`).
   - Check **Import file has column headers** if applicable.
   - Choose a **Delimiter**: Comma, Tab, or Other.
   - Set the **Date format** (e.g., English – United States).
   - Choose **Import type**: e.g., *Add and Update*.
   - Set **Import options**: *Skip rows in import file with bad data*, *Respect double quotes as a text qualifier*.
   - Click **Next**.
4. **Step 2 – Configure Mapping:**
   - Choose a mapping method: **Map by Header Row**, **Map by Ordinal**, or **Map Manually**.
   - Review how each column in your file (e.g., SubscriberKey, FirstName, LastName, EmailAddress, PhoneNumber, Gender, Age, Country) maps to the corresponding **Data Extension Columns** and their data types (Text, Email, Phone, Number, Locale).
   - Click **Next**.
5. **Step 3 – Review & Import:**
   - Review the summary and confirm the import.

> ⚠️ Note: Supported file types are comma-delimited, tab-delimited, or otherwise delimited files. If the file size exceeds 20MB, the **FTP** option must be used instead of uploading from your computer.

**In simple words:** Importing lets you load hundreds or thousands of customer records at once from a spreadsheet, automatically matching each column in your file to the right field in your Data Extension.

### Quick-Fire Definitions
- **Data Extension** → A custom table within Marketing Cloud containing customer data.
- **Contact Based Data Model** → A data model that uses Data Extensions to store and relate customer information.
- **Primary Key** → The field that uniquely identifies each record/row in a Data Extension.
- **Send Relationship** → A link between a Data Extension and Subscribers (via Subscriber Key) that enables sending.
- **Import** → The process of bulk-loading records into a Data Extension from a file.
