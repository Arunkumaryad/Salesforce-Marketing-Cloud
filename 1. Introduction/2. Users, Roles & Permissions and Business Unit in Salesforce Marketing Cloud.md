## 1. Accessing Marketing Cloud

Marketing Cloud is accessed via a dedicated login URL:

- **URL:** `https://mc.exacttarget.com`

This is the entry point (login portal) used to sign in to Salesforce Marketing Cloud, which was originally built on the ExactTarget platform (hence the domain name).

---

## 2. Users in Marketing Cloud

All user management happens inside **Setup**, accessible from the top-right profile menu (`Settings > Setup`).

Path: **Setup → Administration → Users**

From here you can see the full list of users in the org, including:
- **Name**
- **Email Address**
- **Username**
- **Last Login**
- **Status** (Enabled/Disabled)
- **MFA** (Multi-Factor Authentication status)
- **Single Sign-On**
- **External Key**

Under **Administration**, the key sub-sections are:
- **Users → Roles** (manage role definitions)
- **Users → Users** (manage individual user accounts)
- **Business Units**
- **Data Management**

---

## 3. Creating a New User

Steps to create a new user:

1. Go to **Setup → Administration → Users → Users**.
2. Click **Create**.
3. Fill in the **General Settings** form:
   - **Name**
   - **Reply Email Address**
   - **Add to From Name Dropdown** (checkbox)
   - **Notification Email Address**
   - **Username**
   - **External Key**
   - **Time Zone**
   - **Culture Code** (language/locale, e.g., English – United States)
   - **API User** (checkbox — enable if this user is used for API access)
   - **Temporary Password**
   - **Verify Password**
4. Click **Save**.

Once saved, the user's profile page displays all these details along with:
- **Enabled** status (Yes/No)
- **Salesforce.com Status** (Integrated / Not Integrated)
- **Last Login**, **Created**, and **Modified By** timestamps

> ⚠️ Note: After saving, Marketing Cloud may show a message like *"Save successful. To send emails from this domain, request a verification for the domain,"* since a new sender domain isn't verified by default.

## 4. Assigning Roles to a User

By default, a newly created user has **no roles assigned**. To assign roles:

1. Go to **Users**, select the checkbox next to the user's name.
2. Click **Manage Roles**.
3. On the **Roles** page, click **Edit Roles**.
4. Check the roles you want to assign — options include:
   - Administrator
   - Analyst
   - Content Creator
   - Data Manager
   - Distributed Sending User
   - Marketing Cloud Administrator
   - Marketing Cloud Channel Manager
   - Marketing Cloud Content Editor/Publisher
   - Marketing Cloud Security Administrator
   - Marketing Cloud Viewer
5. Click **Save**.

Once saved, a confirmation appears: *"The roles have been assigned"*, listing the roles now attached to the user (e.g., Administrator, Marketing Cloud Administrator).

---

## 5. User Roles — Definitions & Permissions

| Marketing Cloud Role | Permission |
|---|---|
| **Marketing Cloud Administrator** | Assigns Marketing Cloud roles to users and manages channels, apps, and tools. Applies to all Marketing Cloud functionality **except Email Studio**. |
| **Marketing Cloud Viewer** | Shows cross-channel marketing activity results in Marketing Cloud. The most restrictive role — does **not** allow creation, sending, or reporting activities. |
| **Marketing Cloud Channel Manager** | Creates and executes cross-channel interactive marketing campaigns and administers specific channels. Permits creating, sending, and monitoring Marketing Cloud journeys and messages, including reports. |
| **Marketing Cloud Security Administrator** | Maintains security settings and manages user activity and alerts. Assign to someone responsible for determining user access and working with Marketing Cloud security. |
| **Marketing Cloud Content Editor/Publisher** | Creates and delivers messages through applicable channel apps. Permits creating and sending Marketing Cloud journeys and messages, but does **not** include access to many reports. |

---

## 6. Email Studio Roles

Email Studio has its own separate set of roles, since the Marketing Cloud Administrator role does **not** cover Email Studio by default:

| Role | Permission |
|---|---|
| **Administrator** | Access to all Email Studio functions including Setup, email creation, and creating data extensions. |
| **Content Creator** | Access to all content, shared folders, and tracking in Email Studio, but **no access** to data or administrative features. |
| **Data Manager** | Access to everything in Email Studio **except** email content. |
| **Analyst** | Access to tracking features in Email Studio only. |

---

## 7. Managing Individual Permissions

Beyond broad roles, individual permissions can be fine-tuned for a user:

1. On the user's **Roles** page, go to **Permissions → Edit Permissions**.
2. A permissions matrix is displayed, listing modules such as:
   - Salesforce Marketing Cloud
   - MobileConnect
   - Automation Studio
   - Email
   - Discover
   - **Administration** (Users, Business Units, Roles, Account, General, Webhooks, Installed Packages, Content Builder Admin, Custom Domains, Cross Cloud Integration)
   - Approvals (Email)
   - MobilePush
   - Journey Builder
   - Reports
3. For each module/sub-module, you can toggle **Allow** or **Deny** at an **Individual** level (overriding what a role would otherwise grant).
4. Click **Save**.

**In simple words:** Roles give broad, pre-packaged access; Permissions let you fine-tune or restrict specific features for a single user, beyond what their assigned role provides.

---

## 8. Creating a Custom Role

If the pre-built roles don't fit your organization's needs, you can create a **custom role**:

1. Go to **Setup → Administration → Roles**.
2. Click **Create**.
3. Existing default roles are listed with their **External Key** and **Description** (e.g., `SYS_DEF_ADMIN` for Administrator, `SYS_DEF_IMHADMIN` for Marketing Cloud Administrator, etc.).
4. On the **New Role** page, fill in:
   - **Name** (required) — e.g., *Operational Administrator*
   - **External Key**
   - **Description**
5. Under **Permissions**, expand each module (Audience Builder, SocialEngage, Salesforce Marketing Cloud, Marketo, DeveloperApp, MobileConnect, Automation Studio, Email, Discover, CampaignAnalytics, Administration, etc.) and set **Allow**/**Deny** checkboxes as needed.
6. Click **Save**.

**In simple words:** Custom roles let administrators build tailored access profiles — combining exactly the permissions a specific job function needs, rather than using only the built-in role templates.

## 9. MID (Member Identification Code)

**Definition:** A **MID (Member Identification Code)** is a **unique member identification code assigned to every account** in Marketing Cloud.

**In simple words:** Every Marketing Cloud account (including each Business Unit) has its own unique numeric ID — the MID — used to identify it within the platform, in API calls, and in support/troubleshooting.

---

## 10. Business Unit

**Definition:** A Business Unit is used to:
- **Control access to information and sharing of information** throughout Marketing Cloud.
- **Maintain hierarchical structure and parent-child relationships** between different units of an organization.

**In simple words:** Business Units let a large organization (e.g., a parent company with multiple brands or regional teams) split Marketing Cloud access into separate, controlled sections — while still keeping them organized under a shared parent account hierarchy.

Business Units list view shows:
- **Name**
- **Description**
- **Parent Name**
- **Number of Users**

Example structure from the walkthrough:
- **Parent:** `peoplewoo consulting pvt ltd` (7 users)
  - **Child:** `Peoplewoo Skills` (56 users)

---

## 11. Creating a Business Unit

1. Go to **Setup → Administration → Business Units**.
2. Click **Create**.
3. Fill in the **Properties**:
   - **Name** (required) — e.g., *Peoplewoo Consulting*
   - **External Key**
   - **Description**
   - **Time Zone** (e.g., GMT+05:30 Chennai, Kolkata, Mumbai, New Delhi)
   - **Date Format** (e.g., English – United States)
   - **Business Unit Parent** (required) — select the parent unit in the hierarchy (e.g., `peoplewoo consulting pvt ltd`)
4. Click **Save**.

> ⚠️ Note: Marketing Cloud warns that *"changes made to your account settings will permanently disconnect your account from the defaults set by your Administrator"* — so Business Unit creation should be done carefully, ideally by an admin who understands the org hierarchy.

### Quick-Fire Definitions
- **MID** → Unique member identification code assigned to every Marketing Cloud account.
- **Business Unit** → Structure to control access/sharing of information and maintain parent-child hierarchy.
- **Role** → A predefined bundle of permissions assigned to a user (e.g., Administrator, Viewer).
- **Permission** → A fine-grained Allow/Deny setting for a specific feature, which can override role-level access.
