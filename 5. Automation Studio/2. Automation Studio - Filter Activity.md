# 2. What is a Filter Activity?

## Salesforce Definition

> **"Apply the logic of a data filter you select to create a group or
> data extension containing records that meet a set of criteria."**

A Filter Activity applies a previously created Data Filter and creates
or refreshes a group/Data Extension containing records that satisfy the
filter. Salesforce also documents that Filter Activity always overwrites
existing rows in the target Data Extension.

### Easy Explanation

Suppose the source DE has:

  SubscriberKey   Name    Country
  --------------- ------- ---------
  SK001           Arun    India
  SK002           Rahul   USA
  SK003           Amit    India
  SK004           John    UK

Filter:

``` text
Country = India
```

Result:

  SubscriberKey   Name   Country
  --------------- ------ ---------
  SK001           Arun   India
  SK003           Amit   India

So the concept is:

``` text
Source Data Extension
        ↓
     Data Filter
 Country = India
        ↓
    Filter Activity
        ↓
Target Data Extension
```

# 3. Data Filter vs Filter Activity

This is an important interview question.

  Data Filter                   Filter Activity
  ----------------------------- ------------------------------------
  Defines the filtering logic   Applies the filtering logic
  Created in Email Studio       Used in Automation Studio
  Example: Country = India      Runs that filter during automation
  Reusable definition           Automation activity
  Defines qualifying records    Produces/refreshes the result

### Easy Memory Trick

> **Data Filter = What should qualify?**

> **Filter Activity = Apply that rule.**

Salesforce documents that Data Filters are created in Email Studio and
then selected when creating a Filter Activity.

# 7. Data Filter

A Data Filter defines conditions used to segment subscribers or Data
Extension records.

Example:

``` text
Country is equal to India
```

Other examples:

``` text
Age is greater than 18
```

``` text
Gender is equal to Male
```

``` text
Country = India
AND
Age > 18
```

Salesforce describes Data Filters as conditions evaluated against
subscriber attributes or Data Extension fields using an attribute/field,
operator, and comparison value.

------------------------------------------------------------------------

# 8. AND vs OR

## AND

All conditions must be true.

``` text
Country = India
AND
Age > 18
```

## OR

At least one condition must be true.

``` text
Country = India
OR
Country = USA
```

Use **AND** when every condition must match.

Use **OR** when any condition can match.

### Important Workflow Principle

If the Filter Activity is intended to prepare the audience for an email,
normally put the Filter Activity **before** the Send Email activity:

``` text
Schedule
   ↓
Filter
   ↓
Target Data Extension
   ↓
Send Email
```

Otherwise the email could execute before the target is refreshed.

## 22. Step-by-Step Example — Reordering so Filter Runs Before Send Email

**Scenario:** The automation `InvoiceTransaction_Arun` originally had
`1.1 Send Email (InvoiceEmail_Arun)` in Step 1 and `2.1 Filter
(CustomerFilter__Arun)` in Step 2 — meaning the email could fire before
the filtered audience was ready. The screenshot shows the corrected
version.

| Step | Action | Result |
|---|---|---|
| 1 | Open `InvoiceTransaction_Arun` in Automation Studio. | `SUMMARY: 10/3/2026 6:03 AM LAST SAVED`, `WORKFLOW: 2 ACTIVITIES IN 2 STEPS`, `ACTIVITY: 10/3/2026 5:55 AM COMPLETED`. |
| 2 | Drag the **Filter** activity so it sits in **Step 1**, and move **Send Email** to **Step 2**. | Workflow now reads: `Step 1: 1.1 Filter → CustomerFilter__Arun` then `Step 2: 2.1 Send Email → InvoiceEmail_Arun`. |
| 3 | Confirm the **Schedule** starting source is **Active** (green), with `REPEAT: Every 1 day`, `STARTING: 10/03/2026 8:11 PM`, `ENDING: after 7 times`, `TIME ZONE: (GMT+05:30) Chennai, Kolkata, Mumbai, New Delhi`, `NEXT RUN: 10/03/2026 8:41 AM`. | The schedule is active and will run the corrected order automatically every day. |
| 4 | Click **Save**. | The reordered automation is saved: Filter now always runs first, refreshing `customerAutoFilterDE__Arun` before the email reads it. |

### Why order matters

``` text
WRONG ORDER                    CORRECT ORDER
Step 1: Send Email              Step 1: Filter
Step 2: Filter                  Step 2: Send Email
→ email may use stale data      → email always uses the freshly filtered audience
```

# 23. Run Once

The screenshot shows:

``` text
Run Once
```

### Meaning

Run Once manually starts the automation instead of waiting for its next
scheduled occurrence.

Example:

``` text
Automation
    ↓
Run Once
    ↓
Filter Activity executes
    ↓
Target DE is refreshed
```

This is very useful for testing.

## 23A. Step-by-Step Example — Running Only the Filter Step with Run Once

**Scenario:** You want to manually refresh just the filtered audience
(`2.1 Filter — CustomerFilter__Arun`) without re-sending the invoice
email, to check the filter result before the next scheduled run.

| Step | Action | Result |
|---|---|---|
| 1 | Open `InvoiceTransaction_Arun` and click **Run Once**. | Automation Studio opens the **Run Activities** screen with `Step 1` (`1.1 Send Email`, unchecked) and `Step 2` (`2.1 Filter — CustomerFilter__Arun`, checked/highlighted), plus **Select All Activities** / **Clear** controls. |
| 2 | Leave only **Step 2 — 2.1 Filter** checked, and leave **Step 1 — 1.1 Send Email** unchecked. | Only the Filter activity will run this time; the message `Current Workflow configuration has not run` is shown until you click Run. |
| 3 | Click **Run** (top-right). | A **Run Once Confirmation** dialog opens: *"You are about to run InvoiceTransaction_Arun. Click Run Now to run this automation."* |
| 4 | Review the dialog's panels: **Run these activities** (`Step 2 → 2.1 Filter → CustomerFilter__Arun`), **Do not run these activities** (`Step 1 → 1.1 Send Email → InvoiceEmail_Arun`), and **Notification Settings** (`Send if runtime error or skipped run occurs → arunkumar2023712@gmail.com`, `Send after run once completes → arunkumaryadav6207@gmail.com`). | Confirms the Send Email step will be skipped this run, and who is notified on failure/success. |
| 5 | Click **Run Now**. | Only the `2.1 Filter` activity executes, refreshing the target Data Extension `customerAutoFilterDE__Arun`. The Send Email step is skipped for this manual run. |

### Why partially run an automation

``` text
Use case: You want to verify/refresh the filtered audience
           WITHOUT triggering a real customer-facing send.

How: Uncheck the Send Email step before clicking Run
     → only the checked steps (Filter) execute
     → the unchecked steps appear under "Do not run these activities"
```

After running the Filter step, open the resulting Data Extension to

| Step | Action | Result |

| 2 | Check the header. | `customerAutoFilterDE__Arun` shows a green **✔ Available** status and the note `Created through Automation Studio`. |

# 25. Filter Activity Overwrite Behavior

## Very Important Interview Point

Salesforce states:

> **"The Filter activity always overwrites existing rows in the data
> extension."**

Example:

``` text
Before:
Target DE = 100 records
```

After a filter run:

``` text
Current matching records = 40
```

Target becomes:

``` text
40 records
```

It does not simply append those 40 to the existing 100.

### Interview Question

**Does Filter Activity append records?**

**Answer:** No. Filter Activity overwrites the existing rows in the
target Data Extension with the current filter result.

# 27. Data Filter vs SQL Query

  -----------------------------------------------------------------------
  Data Filter                         SQL Query
  ----------------------------------- -----------------------------------
  Graphical                           SQL-based

  Good for straightforward            Good for complex processing
  segmentation                        

  Uses fields, operators and values   Uses SELECT, WHERE, JOIN, GROUP BY,
                                      etc.

  Used by Filter Activity             Used by SQL Query Activity

  Easier for simple conditions        Better for joins and
                                      transformations
  -----------------------------------------------------------------------

### Data Filter

``` text
Country = India
AND
Age > 18
```

### SQL Query

``` sql
SELECT
    SubscriberKey,
    FirstName,
    EmailAddress,
    Country
FROM CustomerProfileDE_Arun
WHERE Country = 'India'
AND Age > 18
```

# 28. When to Use Filter Activity

Use Filter Activity when:

-   A Data Filter already exists.
-   The segmentation is straightforward.
-   A graphical condition builder is sufficient.
-   You want to refresh a target Data Extension as part of an
    automation.
-   You want to reuse the filter definition.

Example:

``` text
All Customers
      ↓
Country = India
      ↓
Indian Customers DE
```

------------------------------------------------------------------------

# 29. When to Use SQL Query Activity

Use SQL Query when you need:

-   JOINs
-   Aggregations
-   Data transformations
-   Complex WHERE conditions
-   Data Views
-   Multiple Data Extensions
-   More control over target data

Example:

``` text
Customer DE
     +
Transaction DE
     ↓
SQL JOIN
     ↓
High Value Customer DE
```

# 34. Why Target DE May Show 0 Records

If the resulting Data Extension initially shows:

``` text
0 Records
```

check:

1.  Has the automation run?
2.  Did you click Run Once?
3.  Is the automation paused?
4.  Does the source DE contain records?
5.  Do records satisfy the filter?
6.  Is the correct Data Filter selected?
7.  Is the correct source DE selected?
8.  Is the target Data Extension correct?
9.  Did the activity complete successfully?

Creating the Filter Activity does not itself mean that the target has
already been populated.

# 38. Best Practices

-   Use meaningful names.
-   Add descriptions.
-   Keep source and target DE names clear.
-   Test filters with a small audience.
-   Verify the target DE before a large send.
-   Put dependent activities in the correct order.
-   Monitor automation history.
-   Remember overwrite behavior.
-   Use SQL Query for complex joins/transformations.
-   Document the source, filter logic, target, and schedule.
-   Test with Run Once before activation where appropriate.

# 49. Final Summary

The complete Filter Activity process is:

``` text
CREATE SOURCE DE
       ↓
CREATE DATA FILTER
       ↓
DEFINE CONDITIONS
       ↓
CREATE FILTER ACTIVITY
       ↓
SELECT FILTER DEFINITION
       ↓
CONFIGURE RESULTING DE
       ↓
ADD TO AUTOMATION
       ↓
CONFIGURE SCHEDULE
       ↓
SAVE
       ↓
RUN ONCE / ACTIVATE
       ↓
VERIFY TARGET DE
```

### Core concept

> **Data Filter defines the rule.**

> **Filter Activity executes the rule.**

> **Filtered Data Extension stores the matching records.**

> **Automation Studio schedules and orchestrates the process.**
