# Automation Studio Introduction


------------------------------------------------------------------------

## 1. What is Automation Studio?

### Definition shown in the training screenshot

> **“It is a Marketing Cloud application used to execute multi-step
> marketing and data management activities on an immediate, triggered or
> scheduled basis.”**

The screenshot also highlights:

- ETL (Extract, Transform, Load) capabilities.
- Advanced segmentation and filtering.
- Import, export, decrypt and other data operations from external
  sources.
- Automation of data management and processes for advanced messaging.

### Easy explanation

**Automation Studio** is a workflow automation tool in Salesforce
Marketing Cloud Engagement.

It is mainly used when you want Marketing Cloud to perform a series of
tasks automatically instead of doing each task manually.

Example:

``` text
Schedule
   ↓
SQL Query
   ↓
Filter
   ↓
Send Email
   ↓
Data Extract
   ↓
File Transfer
```

Salesforce describes Automation Studio as a tool for automating email
sends, queries, imports, and other marketing/data-management workflows.
Activities are the building blocks of an automation.

------------------------------------------------------------------------

## 2. Why Do We Use Automation Studio?

Automation Studio is useful when a process needs to run:

- At a particular time.
- Repeatedly, such as daily or weekly.
- When a file arrives.
- After data has been prepared.
- Before an email is sent.
- After data is transformed or segmented.
- For exporting data to an external system.
- For importing data from an external source.
- For advanced segmentation using SQL or filters.

### Example

A company wants to send a daily birthday email.

``` text
Schedule
   ↓
SQL Query
   ↓
Birthday Customer Data Extension
   ↓
Send Email
```

Instead of manually finding customers, creating the audience, and
sending the email every day, the automation performs the process
automatically.

# 6. Starting Sources

A **Starting Source** determines how an automation begins.

The current interface shown in the screenshots contains:

1.  Schedule
2.  File Drop
3.  Trigger

------------------------------------------------------------------------

## 6.1 Schedule

### Definition shown in the training screenshot — "Scheduled Entry Source"

> **"Schedule: start the automation when you want the data and
> messaging actions that the automation performs to occur at specific
> intervals."**

### Definition

A **Schedule** starts the automation at a configured date/time and
recurrence.

Example:

``` text
Every Day
at 8:00 AM
```

Common use cases:

- Daily email.
- Weekly report.
- Daily SQL processing.
- Recurring data cleanup.
- Scheduled exports.

------------------------------------------------------------------------

## 6.2 File Drop

### Definition

A **File Drop** starts an automation when a matching file is uploaded to
the configured Marketing Cloud Enhanced SFTP location.

Example:

``` text
customer_2026_09_24.csv
          ↓
File Drop
          ↓
Data Copy or Import
          ↓
SQL Query
          ↓
Send Email
```

File name pattern or configured directory can determine whether the
automation starts.

------------------------------------------------------------------------

## 6.3 Trigger

A **Trigger** starts an automation through an external trigger
mechanism.

Current Salesforce documentation describes a trigger starting source as
a way to start an automation when a file is uploaded to an external
location such as AWS, Azure, or Google Cloud and a Trigger API request
fires.

Conceptually:

``` text
External System
      ↓
Trigger / API
      ↓
Automation Studio
      ↓
Activities
```

# 7. Automation Studio Activities

### Definition shown/used in the training

> **Activities are the building blocks of an automation.**

An activity performs a specific action.

Examples:

- SQL Query → processes data.
- Filter → filters records.
- Send Email → sends an email.
- Data Extract → creates an extract file.
- File Transfer → moves/processes files.
- Wait → pauses the workflow.
- Script → executes server-side JavaScript.

------------------------------------------------------------------------

# 8. Data Copy or Import

### Purpose

The **Data Copy or Import** activity updates a subscriber list or Data
Extension using an external file or copies large datasets into a Data
Extension.

Example:

``` text
CSV File
   ↓
Data Copy or Import
   ↓
Customer Data Extension
```

Typical use case:

``` text
Customer.csv
     ↓
File Drop
     ↓
Data Copy or Import
     ↓
Customer_DE
```

------------------------------------------------------------------------

# 9. Data Extract

### Purpose

The **Data Extract** activity creates a file from Marketing Cloud data
for use outside Marketing Cloud Engagement.

It can also perform supported file transformations.

Example:

``` text
Customer_DE
    ↓
Data Extract
    ↓
Customer_2026_09_24.csv
```

Common use cases:

- Export Data Extension records.
- Create files for an external system.
- Prepare files for SFTP transfer.
- Generate reporting datasets.

### Interview point

If Data Extract produces a file and File Transfer processes that file,
place them in the correct sequence so File Transfer does not attempt to
process the file before it is ready.

------------------------------------------------------------------------

# 10. File Transfer

### Purpose

The **File Transfer** activity handles file movement/processing between
configured Marketing Cloud file locations.

It can be used to:

- Move files from Safehouse.
- Unzip files.
- Decrypt files where applicable.
- Transfer files to a configured FTP location.

Example:

``` text
Data Extract
     ↓
Safehouse
     ↓
File Transfer
     ↓
External FTP
```

------------------------------------------------------------------------

# 11. Filter Activity

### Purpose

A **Filter** activity applies filter criteria to create a subset of
records.

Example:

``` text
Customer_DE
     ↓
Filter
     ↓
Active_India_Customers
```

If the Data Extension contains 10,000 records, a filter can create a
subset such as:

``` text
Country = India
AND
Status = Active
```

### Interview point

Filter Activity is useful for straightforward filtering conditions. SQL
Query is more flexible for joins, calculations, Data Views, and complex
transformations.

------------------------------------------------------------------------

# 12. SQL Query Activity

### Purpose

The **SQL Query** activity retrieves and processes data using SQL and
stores the result in a Data Extension.

Common uses:

- Segmentation.
- Joining Data Extensions.
- Preparing email audiences.
- Working with Data Views.
- Data transformation.
- Removing duplicates.
- Reporting datasets.

Example:

``` sql
SELECT
    SubscriberKey,
    FirstName,
    EmailAddress
FROM CustomerProfile
WHERE Status = 'Active'
```

Flow:

``` text
Source Data Extension
          ↓
       SQL Query
          ↓
Target Data Extension
```

### Important

Before configuring a SQL Query Activity, create a target Data Extension
that can store the query results.

# 19A. Step-by-Step: Activating and Pausing a Schedule

The screenshots walk through toggling a schedule between **Active** and
**Paused** on a real automation named `InvoiceTransaction_Arun` (a
Schedule starting source running an `1.1 Send Email` activity using
message `InvoiceEmail_Arun`).

## Step-by-step example — Activating a paused schedule

| Step | Action | Result |
|---|---|---|
| 1 | Open the automation `InvoiceTransaction_Arun` in Automation Studio. The schedule toggle currently shows `Paused` selected, with a note: *"The schedule is suspended and must be activated for scheduled..."* | Automation is not running automatically. |
| 2 | Click the **Active** toggle (left of the Paused toggle). | An **Activate Schedule Confirmation** dialog opens. |
| 3 | Review the confirmation details: `REPEAT: Every 1 day`, `STARTING: 09/24/2026 8:11 PM`, `ENDING: after 7 times`, `TIME ZONE: (GMT+05:30) Chennai, Kolkata, Mumbai, New Delhi`, `NEXT RUN: 09/24/2026 8:11 PM`. | Confirms exactly when the automation will first run and how often. |
| 4 | Click **Activate**. | The automation is saved and activated on that schedule. |
| 5 | The schedule panel now shows the **Active** toggle highlighted in green, and the details update to show a computed `NEXT RUN: 09/24/2026 8:41 AM` and a **Skip Next Occurrence** link. | The automation will now run automatically every day per the schedule. |

## Step-by-step example — Pausing an active schedule

| Step | Action | Result |
|---|---|---|
| 1 | On the same automation, with **Active** currently selected (green), click the **Paused** toggle. | A **Pause Schedule Confirmation** dialog opens. |
| 2 | Read the warning: *"When Paused, the schedule will be suspended and this automation will not run automatically. The automation can still be run manually by clicking Run Once. If you want to resume the schedule, set the schedule toggle to Active."* | Confirms Paused ≠ deleted — it can be resumed anytime, and manual runs are still possible. |
| 3 | Click **Pause**. | The automation stops running on its schedule. |
| 4 | The schedule panel now shows **Paused** highlighted in orange, and the schedule details reappear (`REPEAT: Every 1 day`, etc.) with the suspended-schedule note. | The automation is safely paused; `Run Once` and `Save` remain available. |

### Quick memory trick

``` text
Active  → runs automatically on schedule
Paused  → schedule suspended, but Run Once still works manually
Activate/Pause always shows a confirmation dialog before applying
```

# 20. Run Once

Automation Studio provides:

``` text
Run Once
```

This is useful when you want to manually execute an automation without
waiting for the next scheduled occurrence.

Example:

``` text

```

If you need to execute it now for testing, **Run Once** can be used
where available.

## Step-by-step example — Running `InvoiceTransaction_Arun` once

| Step | Action | Result |
|---|---|---|
| 1 | Open the automation `InvoiceTransaction_Arun`. | The Overview tab shows `WORKFLOW: 1 ACTIVITY IN 1 STEP` and `ACTIVITY: NO ACTIVITY` (never run yet). |
| 2 | Click **Run Once** in the top-right corner. | Automation Studio switches into a **Run Activities** selection screen showing `Step 1` with `1.1 Send Email — InvoiceEmail_Arun`, plus **Select All Activities** / **Clear** controls and the message `Current Workflow configuration has not run`. |
| 3 | Confirm `1.1 Send Email` is checked, then click **Run** (top-right). | A **Run Once Confirmation** dialog opens. |
| 4 | Review the dialog's three panels: **Run these activities** (`Step 1 → 1.1 Send Email → InvoiceEmail_Arun`), **Do not run these activities** (empty), and **Notification Settings** (`Send if runtime error or skipped run occurs` / `Send after run once completes`, each with a Recipient Email Addresses box). | You can confirm exactly which activities will run and who gets notified. |
| 5 | Click **Run Now**. | The automation executes immediately, outside its normal schedule. |
| 6 | Go to the **History** tab (or the Activity panel). | The Run Log shows `Run Once - Complete`, `Started: 09/23/2026 12:41 PM`, `Completed: 09/23/2026 at 12:42 PM`. |
| 7 | Check the **Health** panel on the left. | `Success Rate: 100% (1 Completed)`, `Error Rate: 0% (0 Failed)`, `Average Run Time: 1m 13s`. |

### Quick memory trick

# 38. Sequential vs Parallel Activities

## Sequential

``` text
Step 1:
SQL Query

      ↓

Step 2:
Filter

      ↓

Step 3:
Send Email
```

Use sequential execution when one activity depends on another.

Example:

``` text
SQL Query
   ↓
Target DE populated
   ↓
Send Email
```

The email should not run before the audience data is ready.

------------------------------------------------------------------------

## Parallel

Independent activities can be placed so they run without waiting for
each other.

Example:

``` text
              Schedule
                 |
       +---------+---------+
       |                   |
       v                   v
   Send Email          Data Extract
```

Use parallel processing only when the activities are independent.

# 39. Wait Activity

### Purpose

The **Wait** activity pauses an automation for a configured duration or
until a configured time before continuing.

Example:

``` text
Send Email
    ↓
Wait 24 Hours
    ↓
SQL Query
```

Useful when the next process must happen after a delay.

## Step-by-step example — Building a 4-step automation: Email → Wait → Push → SMS

**Scenario:** After the invoice email goes out, wait 10 minutes, then
send a push notification, then send an SMS — all inside the same
automation `InvoiceTransaction_Arun`.

| Step | Action | Result |
|---|---|---|
| 1 | With `1.1 Send Email — InvoiceEmail_Arun` already in **Step 1**, scroll the **Activities** panel to find `Send Push` and `Send SMS` under **Activities**. | Both new activity types are visible: `Send Push` (phone icon) and `Send SMS` (phone icon). |
| 2 | Drag **Send Push** into **Step 2** and click **Choose** to select the push message. | `1.2 Send Push` is added, showing a `Choose` button until a message is selected. |
| 3 | Drag **Send SMS** into **Step 3** and click **Choose** to select the SMS message. | `1.3 Send SMS` is added, also showing `Choose` until a message is selected. Note: at this point the **WORKFLOW** summary shows `2 UNDEFINED ACTIVITIES` until both Push and SMS messages are chosen. |
| 4 | To add a delay before the push notification, drag the **Wait** activity into **Step 2** instead (pushing Send Push to Step 3 and Send SMS to Step 4). | Layout becomes: `Step 1: Send Email → Step 2: Wait → Step 3: Send Push → Step 4: Send SMS`. |
| 5 | Click **Configure** on the `2.1 Wait` tile. | The **2.1 Wait** dialog opens: *"How long should the Automation wait before running next step?"* with two options — **Duration** (a number + unit dropdown, e.g. Minute(s)/Hour(s)/Day(s)) or **Specific Time** (a time + time-zone dropdown). | 
| 6 | Select **Duration**, enter `10`, choose unit `Minute(s)`, then click **Ok**. | The Wait tile updates to show `2.1 Wait — 10 Minutes`. |
| 7 | Configure the `3.1 Send Push` and `4.1 Send SMS` activities by clicking **Choose** on each and selecting the respective push/SMS message. | The workflow is complete: `1.1 Send Email (InvoiceEmail_Arun) → 2.1 Wait (10 Minutes) → 3.1 Send Push → 4.1 Send SMS`. |
| 8 | Click **Save**. | The 4-step automation is saved; it will run Email, wait 10 minutes, then Push, then SMS, in that order, every time it executes. |

### Easy explanation of the Wait configuration options

``` text
Duration       → wait a fixed length of time (e.g. 10 Minutes, 2 Hours, 1 Day)
Specific Time  → wait until a fixed clock time in a chosen time zone
                 (e.g. 12:00 AM, GMT-06:00 Central Time)
```

### Quick memory trick

``` text
Send Push  = MobilePush notification activity
Send SMS   = MobileConnect SMS activity
Wait       = pauses the automation between steps (Duration or Specific Time)
Undefined Activities = activities added but not yet configured (no message chosen)
```

## 46.1 Health Panel and Notification Settings

The **History/Overview** screen for a completed automation shows a
**Health** panel and a **Notification Settings** panel side by side with
the **Run Log**.

### What the Health panel shows

``` text
Success Rate   : 100%  (1 Completed)
Error Rate     : 0%    (0 Failed)
Average Run Time: 1m 13s   [Reset button available]
```

### What the Notification Settings panel shows

> "Enter email addresses to be notified upon the failure or success of
> the run. Separate multiple addresses with a comma."

``` text
Runtime Error or Skipped Run  → notify these addresses if the run fails or is skipped
Run Completion                → notify these addresses when the run finishes successfully
```

### Step-by-step example — Reviewing history and setting up notifications

| Step | Action | Result |
|---|---|---|
| 1 | Open `InvoiceTransaction_Arun` and click the **ACTIVITY** tab (showing `9/23/2026 12:42 PM COMPLETED`). | The History/Overview screen opens with **Health**, **Notification Settings**, and **Run Log** panels. |
| 2 | Check the **Health** pie chart and numbers. | Confirms `100%` success, `0%` errors, and an average run time of `1m 13s` for this automation. |
| 3 | In the **Run Log**, review the entry: `Run Once - Complete`, `Started: 09/23/2026 12:41 PM`, `Completed: 09/23/2026 at 12:42 PM`, with a green mail icon showing the Send Email activity ran. | Confirms exactly when the run started/finished and which activity executed. |
| 4 | In **Notification Settings**, enter an email under **Runtime Error or Skipped Run**, e.g. `arunkumar2023712@gmail.com`. | This address is notified only if the automation errors out or a run is skipped. |
| 5 | Enter an email under **Run Completion**, e.g. `arunkumaryadav6207@gmail.com`. | This address is notified every time the automation completes successfully. |
| 6 | Optionally click **Add note** under either field to add context for the notification. | A note can be attached to explain why that address is being notified. |
| 7 | Click **Save** on the automation. | The notification settings are stored and will apply to future runs. |

### Quick memory trick

``` text
Health           = Success Rate + Error Rate + Average Run Time
Run Log           = per-run Started/Completed timestamps and status
Runtime Error/Skipped → notify on failure
Run Completion        → notify on success
```

## Topic 4 — SQL Query vs Filter

### SQL Query

Best for:

- JOINs.
- Complex transformations.
- Data Views.
- Calculations.
- Advanced segmentation.

### Filter

Best for:

- Straightforward filtering based on conditions.

### Interview question

**Q: When would you use SQL instead of Filter?**

**Answer:**

Use SQL when the logic requires complex joins, calculations,
transformations, multiple source Data Extensions, or Data Views. Use
Filter when a simpler filtering condition is sufficient.

------------------------------------------------------------------------

## Topic 5 — Data Extract vs File Transfer

### Data Extract

Creates/extracts data into a file.

### File Transfer

Moves/processes files between configured file locations and can handle
operations such as Safehouse transfer, unzip, or decryption where
applicable.

### Interview question

**Q: Why might Data Extract and File Transfer be placed in different
steps?**

**Answer:**

Because File Transfer can depend on the output produced by Data Extract.
Correct sequencing ensures the file exists before the transfer step
processes it.
